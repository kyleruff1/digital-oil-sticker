# Loopback-to-hosted control mapping

**Status:** Draft — owner sign-off pending. Closes [DOS-M09-007](../../planning/issues/DOS-M09-007.md) AC-16 when signed off.
**Authority:** [ADR-0001](ADR-0001-mob-liveview-on-device.md) (deferred), [ADR-0004](ADR-0004-browser-first-client-and-hosting.md), [ADR-0008](ADR-0008-pwa-service-worker-web-push.md), [CONSTITUTION.md](../product/CONSTITUTION.md) INV-22, INV-23, INV-27.

Revision 1.0.0 of the constitution rested a large share of its privacy posture on a physical fact: the Phoenix endpoint bound `127.0.0.1`, so nothing off-device could reach it (retired INV-2). [ADR-0004](ADR-0004-browser-first-client-and-hosting.md) retired that fact when the MVP moved to a public Phoenix LiveView application on Fly.io at `digitaloilsticker.com`, and its own words are that the replacement boundary "is weaker in kind and therefore must be stronger in detail."

This document is the one-page mapping that bridges the two threat models. For each pre-pivot loopback-era control it names, it names the browser-first equivalent that carries its protective intent and the evidence that proves the equivalent is in force. It exists so that [DOS-M07-001](../../planning/issues/DOS-M07-001.md) (the rescoped threat-model card, GitHub #63) can consume the M09-007 evidence set instead of re-deriving it, and so that no reviewer has to reconstruct the correspondence from ADR-0001 and ADR-0004 by hand.

The table is normative for the correspondence; the evidence column is a fixed set of pointers. If a control's evidence moves or is renamed, the same PR that moves it updates this table.

## Retired controls

The loopback-era design named two device-local controls whose protective intent does not carry across the pivot because the capability they governed does not exist in a browser. They are recorded here so a future reader does not spend time hunting for their hosted equivalents; there are none, and there are not supposed to be.

- **`mob_notify` / OS-scheduled local notifications.** ADR-0001 §4 routed every device capability, notifications first, through `DigitalOilSticker.DeviceCommandBroker` and its pinned `Mob.Socket` boundary; the ADR-0001 constitution invariant INV-17 required "OS-scheduled local notifications only." Superseded by [ADR-0004](ADR-0004-browser-first-client-and-hosting.md) §"Consequences → Lost, honestly" ("No OS local notifications. `mob_notify` and OS-scheduled local notifications do not exist in a browser. The MVP ships in-app due/overdue state only, computed on hydration and after each mutation.") and the terminating verdict in [ADR-0008](ADR-0008-pwa-service-worker-web-push.md) H3 (Web Push no-go: a Web Push subscription is "a per-device, server-side endpoint plus keys" that would breach INV-3 and INV-23, and delivery requires a third-party service that would breach INV-4 and INV-22). No hosted equivalent exists and none is planned. The FR-11 absence-guard at [`no_deferred_capability_controls_test.exs`](../../app/test/digital_oil_sticker_web/live/no_deferred_capability_controls_test.exs) refuses the browser affordances (push permission requests, push subscription registration, background sync registration) that would quietly reintroduce the capability.
- **Native permission prompts (camera, microphone, geolocation, notifications, contacts).** ADR-0001's on-device architecture would have surfaced OS permission dialogs at first use of each capability, mediated by the `DeviceCommandBroker`. Superseded by [ADR-0004](ADR-0004-browser-first-client-and-hosting.md) §"Content Security Policy", which serves a `Permissions-Policy` denying geolocation, camera, microphone, payment, USB, magnetometer, and gyroscope on every response — the browser will not present a permission prompt for a capability the response header denies. There is no native OS permission surface to inventory; the header is the whole story. A future VIN-scan feature would need camera and is therefore a separate decision that amends this header, "not a quiet relaxation of it" (ADR-0004 §"Content Security Policy"). Enforcement: [`security_headers_test.exs`](../../app/test/digital_oil_sticker_web/security_headers_test.exs) asserts the `Permissions-Policy` set on every response.
