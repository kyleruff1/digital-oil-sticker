> **RESCOPED FOR BROWSER MVP — 2026-08-01.** [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) established the browser-first MVP. This card is retained with the same identity; its Outcome and functional requirements below are the rescoped spec. The pre-pivot spec is preserved at the bottom under "Superseded pre-pivot spec (historical record)". Disposition per [PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md](../../docs/governance/PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md#issue-by-issue-classification): _The gate still exists but now must freeze a hosted-LiveView-plus-anonymous-browser-storage architecture instead of an on-device one._

## Outcome

Milestone M00 ("Decisions and proof") converts the Digital Oil Sticker product idea into tested constraints and written decisions, then freezes the binding runtime architecture as a **hosted Phoenix LiveView application on Fly.io with anonymous browser storage** for all personal data. The MVP has exactly one deployed Ecto repo — `DigitalOilSticker.CatalogRepo`, opened read-only, per ADR-0004 Decision §4 — and no `UserRepo`, no accounts, and no server-side personal record. Garage, service history, odometer readings, reminder intent, and preferences live in origin-scoped IndexedDB in the user's browser and reach the LiveView only through the ADR-0004 hydration protocol, held in `socket.assigns` for one connection and never persisted. Netlify (team `cDiscourse`) is a static-content boundary only and never the application runtime.

When this epic closes, the product has (a) a ratified Constitution 2.0.0 with the browser-first invariant set (INV-22, INV-23, INV-24, INV-25, INV-26, INV-27) added and the pre-pivot promises (INV-1, INV-2, INV-6, INV-7, INV-17, INV-19) amended or retired in place; (b) a ratified browser-first architecture in ADR-0004 that supersedes ADR-0001 for the MVP, amends ADR-0002, and preserves ADR-0003 unchanged; (c) a ratified vehicle/maintenance data boundary (DOS-M00-006 / ADR-0003) whose legal analysis has been re-reviewed for the new web-serving distribution mode; and (d) a written record that the pre-pivot runtime track is deferred, not deleted, with the DOS-M00-003 physical-device evidence retained for the revival track referenced in ADR-0004 §"Trigger conditions". Every consciously accepted limitation is owned and reviewable.

## Why this matters and what it unblocks

The 2026-08-01 pivot moved the delivery vehicle without changing the product's value. That value is **vendoring** — acquiring, rights-clearing, normalizing, and honestly serving automobile plus oil/filter data — and it is platform-independent. Freezing a browser-first architecture at M00 prevents the recurring architecture mistakes this roadmap explicitly guards against under the new posture: treating Fly.io as an optional host, treating Netlify as an application host, storing any personal record server-side under an "anonymous" fiction, or letting an implicit LiveView-plus-client-storage seam drift into implementation taste (INV-24 exists precisely because the seam is not free). Every later milestone inherits this gate transitively. M01 (engineering foundation) targets the Fly container image, not a signed device package. M02 (interaction and language model) freezes a responsive web contract with URLs, WCAG 2.2 AA, and pre-hydration first-paint rules. M03 (data acquisition) is the surviving core and executes largely unchanged. M04 (persistence) splits along the new boundary — read-only server catalog plus browser `UserStore` — and M05, M06, M07 build on top. **M09 (hosted browser platform and anonymous client storage) is the new milestone that implements what this gate ratifies**; it is `blocked_by` M00 and M01 and blocks M02, M04, and M05.

No feature milestone may start before this gate. The deferred mobile-client track is not deleted; it re-opens on the triggers in ADR-0004 §"Trigger conditions" via a new ADR (referenced there as a future revival ADR).

## Technical implementation contract

### Components and ownership boundaries

Epic-level tracking issue; the components frozen by this gate are owned by the ratified artifacts and their downstream implementation cards:

- **Hosted Phoenix LiveView application on Fly.io.** Ratified in ADR-0004 Decision §1 and §§"Hosting specifics"; implemented by DOS-M09-005 (deploy pipeline), DOS-M09-006 (custom domain and TLS), and the rescoped DOS-M01-005 (LiveView shell).
- **Server-side `CatalogRepo`, read-only, opened against a SQLite file baked into the Fly image.** Ratified in ADR-0004 Decision §4 and §"Catalog database on Fly"; owned by the rescoped DOS-M04-004 and the new DOS-M09-004 (impersonal catalog-query surface).
- **Browser `UserStore` (IndexedDB `dos_local`) with the object-store layout, envelope, mutation round trip, validation caps, migrations, and multi-tab compare-and-set of ADR-0004.** Owned by DOS-M09-001 (schema) and DOS-M09-002 (adapter) with the hydration protocol owned by DOS-M09-003.
- **Static content boundary on Netlify (team `cDiscourse`) for marketing, support, privacy, and attribution only.** Ratified in ADR-0004 §"ADR-0002 → Amended" and INV-27.
- **Packaged mobile client.** Explicitly out of scope for the deployment; the domain contexts are client-agnostic per ADR-0004 Decision §6 so a future packaged mobile client is one additional client over the same contract, not a rewrite.

The epic itself owns only the gate verdict, the limitation register, and cross-child consistency (for example, that Constitution 2.0.0's invariant renumbering is reflected in every ADR that cites the retired INV-2 or the amended INV-6/INV-7/INV-17/INV-19).

### Data and persistence

Ratified split: (i) server-side `CatalogRepo` opened read-only, exactly one Ecto repo in the deployment, no `UserRepo`, per ADR-0004 Decision §4; (ii) browser IndexedDB `dos_local` with monotonically-versioned envelopes per ADR-0004 §"Storage layout" and §"Schema versioning and migration"; (iii) `localStorage` used **only** for the non-personal `dos_boot_state` hint. There is no personal-data table anywhere in the deployment, and the enforcement tests in ADR-0004 §"Enforcement" gate every release.

### Interfaces and events

The hydration protocol (`local_store:hydrate`, `local_store:put`, `local_store:ack`, `local_store:conflict`) is the ratified transport between the client `LocalStore` hook and the LiveView. The mount → hydrate → mutate → ack round trip and the reconnect / multi-tab / storage-fallback rules are specified in ADR-0004 §"Mount and hydration sequence", §"Mutation round trip", §"Multi-tab consistency", and §"Private browsing and blocked storage". Every LiveView mount begins with `assigns.local_state == :hydrating`; the three states `:hydrating`, `:empty`, and `:storage_unavailable` are distinct and rendered differently (INV-24.3).

### Failure and recovery behavior

A failed child ratification is a stop gate, not a workaround opportunity (FR-8). The failed invariant is documented and a replacement-architecture ADR is opened before M01/M02/M03/M09. Data loss recovery for users is bounded by ADR-0004 §"Export and import": export is the *only* recovery path (INV-5, INV-25), it does not round-trip through the server, and the UI copy carries the prohibited-words list (`backup`, `synced`, `safe`, `we'll remember`, `your account`) from ADR-0004.

### Security and privacy

The retired INV-2 loopback boundary is replaced by ADR-0004 §"Security and privacy boundary for a hosted application" (HTTPS/WSS, HSTS enabled after cert verification, `check_origin` with an explicit host list, CSRF on all HTTP routes and the LiveView socket, a strict CSP with no `'unsafe-inline'` and no external scripts, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Permissions-Policy` denying camera/mic/geolocation/payment, per-IP and per-socket rate limits, and the log-redaction rules that keep VIN/odometer/date/note/vehicle-name out of every log sink). LiveDashboard is disabled in production. The epic verdict MUST confirm that no child evidence leaked secrets, certificates, personal path components, or personal data into the repository or attachments — and MUST record the operator-console honesty caveat rather than overclaiming (ADR-0004 §"LiveDashboard and operator access — stated honestly").

### Accessibility and performance

Provisional targets are set in Constitution 2.0.0 §9 (measured against the new browser reality; the pre-pivot loopback latency budget is void per ADR-0004 R9). The measurable **exit** of M00 requires only that Constitution 2.0.0 §9 name the browser-first targets (time-to-hydrated, LiveView interaction p95 by geography, IndexedDB footprint per record, first-paint payload); the *measurement* is owned by DOS-M07-003 (rescoped). Accessibility is WCAG 2.2 AA across a named browser/AT matrix per the rescoped DOS-M02-002 and DOS-M07-002; the OS-accessibility-API language of the pre-pivot spec is retired for the MVP.
