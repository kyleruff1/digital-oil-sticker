## Outcome

Produce a reproducible, legally distributable, versioned, read-only offline catalog artifact for a rolling 30-model-year scope. The artifact ships as a SQLite file baked into the Fly.io release image (`app/priv/catalog/catalog.sqlite3`, chmod 0444, opened read-only via `CatalogRepo` per [ADR-0004 §"Catalog database on Fly"](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md#catalog-database-on-fly)). It supports deterministic vehicle lookup and, only where licensed evidence exists, oil-service schedules, vehicle lubricant requirements, oil products, and oil-filter fitment. Catalog activation is a Fly deploy: the artifact is built and validated in CI, embedded in a new image, and activated by rolling the new image forward; rollback is redeploying the previous image.

## Why this matters and what it unblocks

The product's non-negotiable rules require that no automotive fact be fabricated, and that every displayed manufacturer interval, viscosity/specification, capacity, oil-product claim, and filter fitment have provenance and a license permitting web serving (per [ADR-0003](../../docs/architecture/ADR-0003-data-boundaries.md) as amended and the re-review in [WEB_SERVING_RIGHTS_REVIEW.md](../../docs/data/WEB_SERVING_RIGHTS_REVIEW.md)). This epic is the only path by which such data legally enters the deployed application. It unblocks M04 (rescoped: local domain and derived state served from the read-only catalog), M05 (single-vehicle MVP flows built on catalog lookup), and M07 (hardening and release, which requires data-quality sign-off). Without this epic there is no vehicle selector, no sourced schedule, and no defensible recommendation claim.

### Data and persistence

N/A — epic-level tracking issue. The binding baseline is the `CatalogRepo` field-level contract in [DATA_DICTIONARY.md](../../docs/data/DATA_DICTIONARY.md) (closed by [DOS-M01-003](DOS-M01-003.md)); M03 populates the empty tables (`maintenance_schedules`, `oil_requirements`, `filter_*`) that ship with zero rows in build 1. ### Interfaces and events

N/A — epic-level tracking issue. The epic's downstream interface is the versioned catalog artifact plus manifest, consumed by the Fly Docker build (`COPY priv priv`) at image bake time and by `CatalogRepo` at boot.

### Failure and recovery behavior

N/A — epic-level tracking issue. Child issues define per-stage failure behavior; the epic-level rule is that rights gates reduce data-backed features and never get bypassed by prohibited crawling, copying protected manual prose/layout/assets, or inventing crosswalks. Catalog activation failure is a Fly deploy failure and is reverted by redeploying the previous image (RELEASE_LEDGER.md §"Rollback target").

### Security and privacy

N/A — epic-level tracking issue, except the binding constraints that secrets/API keys never enter source control, fixtures, manifests, image assets, or logs; and that raw catalog acquisition never contains end-user VINs or personal data ([INV-4](../../docs/product/CONSTITUTION.md), [INV-26](../../docs/product/CONSTITUTION.md)).

### Accessibility and performance

N/A — epic-level tracking issue. Catalog/query size budgets and image-size budgets are enforced in [DOS-M03-010](DOS-M03-010.md) and by the CI job that fails a release image over a threshold.

## UX and content states

N/A — epic-level tracking issue for pipeline and data work; the epic has no direct UI. It does, however, bind the content contract used by later UI milestones: unsupported/unlicensed domains fall back to user-entered values labeled "User entered", never "Manufacturer recommended" or "Compatible"; missing data is shown as unknown or unsupported per INV-11/INV-15/INV-20/INV-21; seed/demo values are synthetic, visually marked, and excluded from production builds.

## Risks, decisions, and open questions

- Risk: commercial licenses (MOTOR, Auto Care, suppliers, API EOLCS) may not be secured on acceptable one-time-snapshot terms; mitigation is the mandatory free-approved baseline plus user-entered fallback, which keeps the app shippable.
- Risk: free-source coverage may be thinner than expected for schedules/fluids/fitment; the quantified gap analysis in DOS-M03-001 bounds procurement to real gaps.
- Risk: NHTSA applies unpublished automated traffic control; DOS-M03-004's conservative courtesy limits mitigate.
- Risk (new under ADR-0004): shipping catalog data over a public network path could expose a source that was safe on-device but not safe served; the [WEB_SERVING_RIGHTS_REVIEW.md](../../docs/data/WEB_SERVING_RIGHTS_REVIEW.md) re-review is the mitigation, and EOLCS remains withheld pending [DOS-M09-010](DOS-M09-010.md).
- Decision recorded: the vPIC standalone downloadable database is VIN-decode-only and is not a candidate for make/model enumeration.
- Decision recorded (new under ADR-0004): catalog activation is a Fly image rollout, not an on-device staged install. The atomic-activation mechanics live in [DOS-M04-008](DOS-M04-008.md) as re-scoped and [DOS-M09-006](DOS-M09-006.md).
- Open question: whether measured Fly image-size budgets require catalog compression or sharding across releases (resolved inside DOS-M03-010 by measurement, not assumption).

## Definition of done

All acceptance criteria checked; every child closed with evidence (or the documented free-approved baseline path satisfied); exit-criteria artifacts produced in CI from pinned inputs; the catalog embedded in the Fly release image and verified by the release-gating tests (`repo_readonly_test.exs`, `fixture_manifest_test.exs`); no unresolved rights violation, QA blocker, or silently waived gate; epic evidence linked from the project tracker.
