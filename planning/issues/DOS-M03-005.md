## Outcome
A resumable build gathers the approved major-make, light-duty year/make/model/type identity set for the rolling 30-year window without runtime network dependence.

## Why this matters and what it unblocks
Vehicle selection, schedule crosswalks, filter crosswalks, catalog sizing, and coverage QA all need a bounded canonical candidate set. This corpus is the identity spine of the entire catalog: DOS-M03-006 normalizes and crosswalks against it, and the source-coverage portions of DOS-M03-010 report against its coverage cells. It also delivers the free-first FuelEconomy.gov configuration-enrichment evaluation demanded by the acquisition strategy.

## Context and source of truth
- Master prompt section 4.4: vPIC supplies the identity spine; the year/make/model endpoint supports years greater than 1995 but does not enumerate every retail trim/engine/build; the free candidate matrix names vPIC for identity/aliases and FuelEconomy.gov / EPA files for configuration clues; vPIC standalone downloads are limited to VIN-decoding functionality.
- Master prompt section 5 "Coverage contract to freeze in M00": U.S. market; rolling 30-model-year window (1997–2026 inclusive for the 2026 baseline); passenger cars, multipurpose passenger vehicles, and light pickups/vans that use engine oil.
- Section 11.2 "Research-backed source policy" (verified 2026-07-31): vPIC API scope and traffic control; NHTSA's statement that standalone databases are VIN-decode-only and that makes, models, variables, and attributes still require the APIs; FuelEconomy.gov (administered by Oak Ridge National Laboratory for DOE and EPA) publishes vehicle web services and downloadable Find-a-Car data for 1984–current model years with stable vehicle IDs plus cylinders, displacement, drive, fuel type, engine descriptor, transmission, and base model.
- Research-anchor URLs: [vPIC API](https://vpic.nhtsa.dot.gov/api/), [vPIC downloads](https://vpic.nhtsa.dot.gov/Downloads), [FuelEconomy.gov Web Services](https://www.fueleconomy.gov/feg/ws/).
- DOS-M03-002: major-make allowlist mechanism, rolling scope formula (`build_calendar_year - 29` through `build_calendar_year`), stable-ID and `_provenance` contracts.
- DOS-M03-004: the only permitted vPIC access path.

## Included
- Materialize the approved major-make allowlist with vPIC make ID, canonical name, aliases, included vehicle types, market rationale, owner, and review date.
- Enumerate every year in the rolling range and approved types (`Passenger Car`, `Multipurpose Passenger Vehicle (MPV)`, and approved light trucks; exact vPIC IDs/names confirmed by discovery fixtures).
- Request models by numeric make ID + year + vehicle type. Deduplicate exact source IDs while retaining multi-type mappings.
- Record explicit coverage status for every `(model_year, make_id, vehicle_type_id)` request: `complete`, `empty_confirmed`, `failed`, `schema_rejected`, `deferred`. An empty response is not silently considered complete until envelope semantics validate.
- Use the vPIC API—not the downloadable standalone/lite database—to enumerate makes, models, vehicle types, variables, and attributes. Add a regression/documentation check citing NHTSA's statement that the standalone database is VIN-decode-only so a later optimization does not accidentally replace the API traversal with an incomplete source.
- Evaluate official FuelEconomy.gov vehicle web services or downloadable Find-a-Car data as a separate, free-first configuration-enrichment source. If its terms pass DOS-M03-001, ingest provider vehicle ID, year, make, model/base model, cylinders, displacement, drive, fuel type, engine descriptor, and transmission into normalized staging; preserve source semantics and crosswalk through DOS-M03-006. Do not allow FuelEconomy.gov rows to overwrite vPIC identity by name or to imply oil/filter compatibility.
- Quarantine model years outside configured scope and non-consumer/specialty vehicle types rather than deleting without report.

## Excluded
- Claiming trim/engine/build completeness from the model endpoint.
- Using vehicle sales volume not licensed to the project.
- Querying user VINs.

## Functional requirements
- FR-1: The approved major-make allowlist is materialized with vPIC make ID, canonical name, aliases, included vehicle types, market rationale, owner, and review date, and is version/SHA-pinned in the run manifest.
- FR-2: The build enumerates every year in the rolling range for every allowlisted make and approved vehicle type (`Passenger Car`, `Multipurpose Passenger Vehicle (MPV)`, and approved light trucks), with exact vPIC type IDs/names confirmed by discovery fixtures rather than hardcoded guesses.
- FR-3: Model requests use numeric make ID + year + vehicle type; exact source IDs are deduplicated while multi-type mappings are retained.
- FR-4: Every `(model_year, make_id, vehicle_type_id)` cell receives exactly one terminal coverage status from `complete`, `empty_confirmed`, `failed`, `schema_rejected`, `deferred`; an empty response becomes `empty_confirmed` only after envelope semantics validate.
- FR-5: Enumeration uses the vPIC API exclusively — never the downloadable standalone/lite database — and an automated regression/documentation check cites NHTSA's statement that the standalone database is VIN-decode-only.
- FR-6: Normalized candidate rows carry `vpic_make_id`, `vpic_model_id`, `vpic_vehicle_type_id`, `model_year`, source spellings, request fingerprint, raw object SHA, and coverage cell ID.
- FR-7: If FuelEconomy.gov terms pass DOS-M03-001, its adapter ingests provider vehicle ID, year, make, model/base model, cylinders, displacement, drive, fuel type, engine descriptor, and transmission into source-namespaced normalized staging with its own provider vehicle IDs and receipts; FuelEconomy.gov rows never overwrite vPIC identity by name and never imply oil/filter compatibility; crosswalking happens only through DOS-M03-006.
- FR-8: Out-of-scope model years and non-consumer/specialty vehicle types are quarantined with a report, not silently deleted.
- FR-9: A run manifest freezes `as_of_date`, year window, allowlist version/SHA, vPIC endpoint/API version when known, optional FuelEconomy.gov dataset version/retrieval date, request counts, and cell totals.
- FR-10: Coverage reporting uses all expected allowlist/year/type cells as the advertised denominator and reports both cell coverage and distinct year/make/model rows.
- FR-11: The run is resumable: warm-cache reruns make zero upstream requests with identical normalized hashes; a checkpointed run resumes after forced termination without duplicate output.

## Technical implementation contract
### Components and ownership boundaries
- Corpus build orchestrator: plans the cell grid (allowlist × years × types), drives the DOS-M03-004 client, assigns terminal statuses, and emits the run manifest; owned by the data pipeline.
- Allowlist materializer: turns the product-owned allowlist into the pinned build input.
- FuelEconomy.gov enrichment adapter (conditionally enabled by rights status): separate module with its own receipts, staging namespace, and coverage report; never writes into vPIC identity rows.
- Quarantine reporter: collects out-of-scope years/types with reasons.
### Data and persistence
- Raw responses in the DOS-M03-003 landing zone with receipts; normalized candidate rows in staging validated against DOS-M03-002 schemas with full `_provenance`.
- Coverage-cell ledger persists one terminal status per cell per run.
- FuelEconomy.gov staging rows remain source-namespaced with provider vehicle IDs, feeding `vehicle_external_ids` in DOS-M03-006 — enrichment and QA evidence only, per section 4.4.
- Downstream fit: rows feed section 8 `makes` (nullable unique `vpic_make_id`), `models` (`vpic_model_id`, unique provider identity), and `vehicle_configurations` candidates.
### Interfaces and events
- Consumes only the DOS-M03-004 typed client API; no direct HTTP.
- Emits: run manifest, coverage CSV/HTML summary, quarantine report, normalized staging hashes — consumed by DOS-M03-006 and the source-coverage portions of DOS-M03-010.
- Product review event: measured catalog scope/size and enumeration strategy presented for approval (AC-6).
### Failure and recovery behavior
- Client failures map to cell statuses (`failed`, `schema_rejected`, `deferred`); the run continues past individual cell failures and reports them; production promotion requires failures above the configurable zero-tolerance threshold to be resolved.
- Forced termination: checkpoint resume without duplicate output; completed cells are never re-fetched on warm cache.
- Upstream drift (schema rejection) quarantines the cell rather than corrupting staging.
### Security and privacy
- No user VINs are ever queried (build-side enumeration only).
- Receipts and logs follow DOS-M03-003 redaction; no payloads at normal log level.
- Sales-volume or other unlicensed datasets are not consulted for allowlist rationale (rationale is product-owned and documented).
### Accessibility and performance
N/A for accessibility — build-side pipeline. Performance/courtesy: the run inherits DOS-M03-004 spacing; total request counts are recorded in the manifest; warm-cache reruns are zero-request; the corpus bounds catalog sizing measurements for DOS-M03-010.
### Data change specifics
- Source/version/license: NHTSA vPIC API (green-lane U.S. government data; terms evidence in the DOS-M03-001 matrix); optional FuelEconomy.gov dataset with its own version/retrieval date, used only if its terms pass DOS-M03-001.
- Mapping: vPIC results → normalized candidate rows (`vpic_make_id`, `vpic_model_id`, `vpic_vehicle_type_id`, `model_year`, source spellings); FuelEconomy.gov rows → separate staging namespace (provider vehicle ID, year, make, model/base model, cylinders, displacement, drive, fuel type, engine descriptor, transmission). No cross-source merging in this issue.
- Stable keys: NHTSA integer IDs as source keys; stable catalog IDs derived per the DOS-M03-002 UUIDv5/namespaced-digest rules; coverage cell ID = `(model_year, make_id, vehicle_type_id)`.
- Constraints/indexes: dedupe on exact source IDs with retained multi-type mappings; one terminal status per coverage cell; staging uniqueness on source ID + model year + type mapping.
- Idempotency: warm-cache rerun → zero upstream requests, identical normalized hashes; checkpoint resume without duplicates.
- Rejected-row policy: `schema_rejected` cells and out-of-scope years/non-consumer types are quarantined with reasons and reported, never silently deleted.
- Checksums: raw object SHA-256 per response; normalized staging hashes recorded in the manifest for rerun comparison.
- Coverage report: cell-status matrix over all expected allowlist/year/type cells plus distinct year/make/model row counts; explicitly states that vPIC does not guarantee complete trims/engines and does not supply oil schedules, fluids, or filters.
- Fixture strategy: discovery fixtures pin exact vPIC vehicle-type IDs/names; sanitized response fixtures cover empty, renamed, multi-type, and rejected cells for CI without live traffic.
- Update cadence: rerun per catalog release or on allowlist/scope change; each run is a fresh manifest; no scheduled polling.
- Rollback/recovery: manifests plus receipts make any prior corpus rebuildable; a bad run is discarded by pinning the previous manifest, since staging outputs are versioned by run.

## Test plan
### Automated
- Cell-grid tests: every expected cell resolves to exactly one terminal status; empty responses become `empty_confirmed` only after envelope validation; failure statuses propagate to the report.
- Cold/warm run comparison: recorded request counts prove zero upstream requests on warm cache; normalized hash equality across reruns.
- Interrupted-run test: forced termination mid-run, resume, and duplicate-free output verification.
- Dedup tests: exact source-ID dedupe with multi-type mapping retention.
- Standalone-scope citation check: automated documentation/regression check asserting the NHTSA VIN-decode-only statement is present and the build has no standalone-database code path.
- Quarantine tests: out-of-scope year and specialty-type fixtures land in the quarantine report.
- FuelEconomy.gov adapter fixtures (if enabled): staging isolation, no identity overwrite by name, provider-ID preservation, independent receipts.
### Manual/device matrix
- Product review session: enumeration strategy, measured scope/size, coverage summary, and quarantine report; recorded approval (AC-6).
- Data-owner spot-check of a sample of `empty_confirmed` cells against the public vPIC site to confirm empties are genuine.
- No device work: N/A — build-side pipeline.

## Rollout and rollback
Each corpus build is a versioned, manifest-pinned output; downstream stages consume a specific run manifest, so promotion is manifest selection and rollback is re-pinning the prior manifest. Allowlist or scope changes produce a new run with diffs reported; no in-place mutation of a published run's staging output.

## Documentation and evidence
Run manifest; coverage CSV/HTML summary; cold/warm request counts; interrupted-run test; NHTSA standalone-scope citation check; optional FuelEconomy.gov adapter/crosswalk report. Plus the materialized allowlist (with owner and review date) and quarantine report.

## Dependency rationale
Depends on DOS-M03-004 — all traffic must flow through the courteous, contract-tested client; enumerating 30 years × allowlist makes × types without its caching, spacing, and resume guarantees would risk request storms against an API with unpublished rate control. Blocks DOS-M03-006 (normalization/crosswalks need the candidate set) and the source coverage portions of DOS-M03-010 (release coverage reporting uses these cells as denominator).

## Risks, decisions, and open questions
- Risk: vPIC type names/IDs differ from planning assumptions; mitigated by discovery fixtures confirming exact IDs/names before enumeration.
- Risk: interpreting empty responses as coverage; mitigated by `empty_confirmed` requiring validated envelope semantics and by manual spot-checks.
- Risk: the corpus is mistaken for a complete trim/engine catalog; mitigated by AC-4's explicit report language and section 4.4's completeness caveats.
- Decision: FuelEconomy.gov is enrichment/QA only, never identity authority and never compatibility evidence.
- Open question: final approved light-truck type set for the allowlist; resolved by the DOS-M03-002 allowlist owner before the production run.

All acceptance criteria checked; corpus build implemented and executed against the pinned allowlist and rolling window; run manifest, coverage summary, quarantine report, and (if enabled) FuelEconomy.gov enrichment reports published; automated suites including cold/warm, interruption, and citation checks green in CI; product approval recorded; DOS-M03-006 and DOS-M03-010 coverage inputs delivered.
