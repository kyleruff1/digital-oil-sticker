> **RESCOPED FOR BROWSER MVP — 2026-08-01.** [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) established the browser-first MVP. This card is retained with the same identity; its Outcome and FRs below are the rescoped spec. The pre-pivot spec is preserved at the bottom under "Superseded pre-pivot spec (historical record)". Disposition per [PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md](../../docs/governance/PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md#issue-by-issue-classification): _Search is a server query over the hosted catalog, so the local-query latency budget becomes a network-plus-server p95 budget and request-failure states become mandatory._

## Outcome

A returning user, or a visitor whose IndexedDB garage has just hydrated (or come up empty), can find an exact supported year/make/model/variant by cascading filters and text search **served by the hosted read-only `CatalogRepo` query layer** ([DOS-M09-005](DOS-M09-005.md)) over the LiveView socket, and commit that selection to the single-vehicle garage in browser IndexedDB through the [DOS-M09-003](DOS-M09-003.md) mutation round trip. Every catalog request carries only impersonal selectors (INV-26); no VIN, odometer, note, or client identifier ever appears in a search payload. Network-latency, catalog-query failure, retry, socket-down, and per-socket rate-limit states are first-class UX states with the ratified §9 network-plus-server p95 budgets, not error toasts. The picker never renders a false empty-garage claim during hydration, never presents a partial or stale catalog page as authoritative on a failed query, and never commits a dangling reference to a catalog `configuration_key` that the current server release does not contain.

## Why this matters and what it unblocks

The dashboard, interval lookup, service record, and forecast cannot be trusted until an exact, catalog-backed vehicle identity is selected and committed to the user's browser store. Recommendation fidelity (INV-15 "no fabricated automotive facts", INV-16 "requirements not brand folklore") begins at selection: an ambiguous or guessed vehicle poisons every downstream sourced claim.

Under [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) the catalog is **not** bundled on-device and there is **no on-device Endpoint or WebView**. The catalog is queried from the hosted Phoenix LiveView application on Fly.io through the read-only `DigitalOilSticker.CatalogRepo` opened by [DOS-M09-005](DOS-M09-005.md). That reshapes this card in three concrete ways that map to the pivot's staleness findings:

- The "entirely offline" clause of the pre-pivot Outcome is contradicted by INV-6 (amended) and by ADR-0004 "the app does not work offline at all"; it is replaced by a network-plus-server search with the honest degradation obligations of INV-7.
- The pre-pivot FR-1 ("locally installed, validated SQLite catalog") and FR-2 ("on-device Endpoint/WebView") describe a distribution mode that no longer exists; they are replaced with a server-queried read context and a hosted LiveView interaction model bounded by INV-22, INV-24, and INV-26.
- The airplane-mode journey (pre-pivot "Manual/device matrix" bullet and pre-pivot AC-2 "network blocked") is retired outright; the equivalent obligations become the catalog-query failure and pending-query states demanded by INV-7 and the §9 catalog-query row.

It unblocks [DOS-M05-003](DOS-M05-003.md) (create/edit vehicle round-trips the committed selection through the [DOS-M09-003](DOS-M09-003.md) mutation protocol into IndexedDB) and [DOS-M05-005](DOS-M05-005.md) (the dashboard renders the committed identity out of hydrated assigns).

## Included

- Progressive filters in the order Year → Make → Model → Variant/trim/body/engine when those dimensions exist, each choice narrowing valid subsequent choices through [DOS-M09-005](DOS-M09-005.md) queries.
- Text search served by [DOS-M09-005](DOS-M09-005.md) with normalization of case, whitespace, punctuation, and documented aliases.
- Result disambiguation display: enough sourced fields (with provenance/support status per INV-11 and INV-15) to prevent ambiguous selection.
- Explicit UX states for pending catalog query, slow query (exceeded the query-response soft threshold), catalog-query failure, socket-down/reconnect (INV-24 remount), and per-socket rate-limit throttling — each visually and textually distinct from `:empty` (INV-24.3) and from `:storage_unavailable` (INV-24.6).
- Retry semantics for a failed catalog query: bounded user-initiated retry, no silent auto-retry storm, backoff aligned with the [DOS-M09-008](DOS-M09-008.md) per-socket rate-limit contract.
- No-result paths for every filter level and for text search, distinguishable in copy from a catalog-query failure (INV-7: "a connection problem is shown as a connection problem, never as 'no data'").
- Catalog provenance and support status on results, sourced from the [DOS-M09-005](DOS-M09-005.md) response envelope.
- Selection review before commit, with safe back navigation that preserves prior valid choices.
- Commit path that writes the selection to the browser `vehicles` object store through the [DOS-M09-003](DOS-M09-003.md) `pushEvent` → hook → IndexedDB → ack round trip, and does not render the commit as saved until the hook acknowledges (INV-24.2).
- Manual "vehicle not listed" feedback guidance that does not transmit any personal data (INV-4, INV-26).
- Precision labeling when only a broad vehicle mapping exists.
- Accessibility of every control per §9: full keyboard operability with visible focus indicator, target size ≥ 24×24 CSS px (≥ 44×44 SHOULD where touch is primary), screen-reader operability including live-region announcement of result-count changes without stealing focus, usable at 200% zoom and at 320 CSS px reflow width.

## Excluded

- Any on-device bundled catalog, on-device SQLite catalog file, on-device `Endpoint`, WebView, or airplane-mode journey — these belong to the deferred native track ([ADR-0001](../../docs/architecture/ADR-0001-mob-liveview-on-device.md) status).
- Any service worker, PWA install path, or offline catalog caching — deferred per [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) and INV-19; a disabled-but-visible control that implies one is also excluded.
- Live VIN decoding.
- Fuzzy guesses that auto-select.
- User-created catalog rows.
- Multiple saved vehicles (INV-18 keeps this post-MVP; internals remain multi-vehicle-safe).
- Any server-side persistence of search history, partial selection, session, IP, or vehicle identity beyond transient `socket.assigns` for the socket lifetime (INV-3, INV-23, INV-24.1).
- Any personal parameter — VIN, odometer, note, free-text field, record identifier, or stable client identifier — in a catalog request payload (INV-26).
- Third-party analytics, error reporters, or any cross-origin beacon on the picker (INV-4, INV-22).

## Functional requirements

- FR-1 (**replaces pre-pivot FR-1**): Every cascade query, every search query, and every configuration-resolve call is issued to the hosted read-only `CatalogRepo` through the [DOS-M09-005](DOS-M09-005.md) query context surfaced on `DigitalOilSticker.Catalog`. The LiveView MUST NOT open a database, read a bundled file, or issue any request to a non-application origin. There is no on-device catalog; there is no local SQLite file for this card to query (INV-1, INV-6 amended, ADR-0004 §"Catalog database on Fly"). (Addresses staleness finding 1: contradiction with ADR-0004 and INV-6.)
- FR-2 (**replaces pre-pivot FR-2**): The picker is a hosted Phoenix LiveView reached over WSS at an owner-controlled domain (INV-1, INV-22, INV-27). Its interaction shape is the LiveView `pushEvent` round trip over the socket; there is no on-device `Endpoint`, no WebView, and no loopback listener. Search and filter events are debounced server-side to respect the [DOS-M09-005](DOS-M09-005.md) latency budget and the [DOS-M09-008](DOS-M09-008.md) per-socket rate-limit contract. (Addresses staleness finding 1: on-device Endpoint/WebView framing retired.)
- FR-3 (**new — network-latency behavior**): Cascade and search interactions render a pending state within one animation frame of the debounce firing; a slow-query state appears when a query exceeds the ratified §9 soft threshold (`server response p95` and `catalog query p95`); the p95 network-plus-server budget is the one ratified in §9 for the deployed environment, not the pre-pivot loopback budget (§9 R9). The pending state is visually distinct from `:hydrating` (INV-24.3) and from `:empty`. (Addresses the pivot line "network-plus-server p95 budget".)
- FR-4 (**new — request-failure and retry**): A failed catalog query — timeout, server error, socket disconnect during the request, or an INV-24 remount that discarded pending assigns — renders the explicit catalog-query-failure state (INV-7), preserves the user's prior valid filter selections, offers a bounded user-initiated retry, does not silently auto-retry, and MUST NOT render a stale or partial catalog page as authoritative. It MUST NOT fabricate a fallback vehicle, interval, or configuration (INV-15). Retry backoff and cap MUST respect the [DOS-M09-008](DOS-M09-008.md) per-socket rate-limit ceiling. (Addresses the pivot line "request-failure states become mandatory".)
- FR-5 (**new — per-socket rate-limit handling**): When [DOS-M09-005](DOS-M09-005.md) or [DOS-M09-008](DOS-M09-008.md) signals per-socket rate-limit throttling, the picker renders a distinct throttled state (never presented as an error toast), pauses further debounced queries until the throttling window elapses, and does not spin, retry-storm, or hide the throttle from the user (INV-7). (Addresses the pivot's explicit "per-socket rate-limit handling" requirement.)
- FR-6 (**replaces pre-pivot "airplane-mode" journey**): This card does not implement, verify, or claim any airplane-mode or fully offline journey. When the LiveView socket is down, the app renders the `phx-disconnected` reconnect state (ADR-0004 §"WebSocket and LiveView considerations"); a picker interaction attempted while disconnected is deferred until reconnect and re-runs against the freshly hydrated assigns. The user's own `vehicles` records in IndexedDB remain readable to the extent renderable without a catalog round trip (INV-7), but no new selection can be committed without connectivity. Copy MUST NOT imply offline capability (INV-19 deferred items). (Addresses staleness finding 1: airplane-mode journey retired.)
- FR-7 (**impersonal query surface**): No catalog request emitted by this card, in a debounced search, a cascade change, a configuration resolve, a "vehicle not listed" submission, or in any header, query string, cookie, or socket payload, MAY carry a VIN, odometer reading, note, free-text personal field, record identifier, `tab_id`, or stable client identifier (INV-4, INV-26). Search text is user-entered vehicle text (year, make, model, trim); it is normalized locally on the server side and parameterized in queries. Request payloads are auditable (see AC-9).
- FR-8: Filter order is Year → Make → Model → Variant/trim/body/engine when those dimensions exist. Each choice narrows valid subsequent choices and clears incompatible downstream selections. Filter state uses stable catalog IDs (never display strings) as foreign keys.
- FR-9: Search normalizes case, whitespace, punctuation, and documented aliases but never collapses distinct engines or variants.
- FR-10: Results display enough fields to prevent ambiguous selection: model year, make, model, variant/trim, engine displacement/cylinders/fuel when sourced, drivetrain/body when needed, and support status. Unknown is shown as "Not specified" (INV-21) and never guessed (INV-11, INV-15).
- FR-11: The final review states that recommendations depend on exact configuration and lets the user go back without losing prior valid choices. If only a broad vehicle mapping exists, the selection carries a visible precision label. Terminology follows INV-21.
- FR-12 (**replaces pre-pivot FR-8, commit through the hydration mutation round trip**): Search/filter state is disposable and lives in socket assigns for the socket lifetime only (INV-24.1). A vehicle is committed only after explicit confirmation, and only through the [DOS-M09-003](DOS-M09-003.md) mutation round trip: server assigns `mutation_id` and `seq`, `push_event`s `local_store:put` to the hook with the vehicle upsert, waits for `local_store:ack`, then renders the saved state. The UI MUST NOT render the commit as saved before the client acknowledges (INV-24.2). Back navigation and tab close before the ack yield no server-side row (there are no server-side rows) and no IndexedDB row.
- FR-13: A result cannot be committed without all catalog-required disambiguating fields; a broad mapping carries a visible precision label at commit and after commit.
- FR-14 (**stale-selection handling for the hosted release cadence**): If a `configuration_key` selected mid-flow becomes unresolvable in the current `data_version` (a Fly release rolled out during the flow), the server MUST return the `Catalog` stale-selection error, restart the affected cascade level, and MUST NOT commit a dangling reference to a non-existent catalog row.
- FR-15 (**multi-tab consistency**): A vehicle committed in Tab A propagates to Tab B via the [DOS-M09-003](DOS-M09-003.md) `BroadcastChannel` + compare-and-set discipline (INV-24.7): Tab B re-hydrates from IndexedDB and the picker in Tab B (if open) surfaces a visible "reloaded from this browser's newer data" notice rather than silently overwriting.
- FR-16 (**failed-ack contract**): If the hook does not `local_store:ack` within the [DOS-M09-003](DOS-M09-003.md) deadline, the server renders the persistent, non-dismissible "Not saved to this browser" state on the vehicle, keeps the optimistic value visible but visibly unsaved, and offers export (INV-24.5). It does not retry silently and does not roll back invisibly.
- FR-17 (**quota-exceeded on commit**): A `QuotaExceededError` on the vehicle write follows the failed-ack path with a quota-specific message and prior state preserved (INV-24.5, ADR-0004 §"Quota and eviction"). Data is never silently dropped to make room.
- FR-18: All controls are keyboard/screen-reader operable, have visible labels and focus indicators, keep target size ≥ 24×24 CSS px (≥ 44×44 SHOULD where touch is primary), remain usable at 200% zoom and 320 CSS px reflow width, and announce result-count changes politely without stealing focus (§9 Accessibility).
- FR-19: The "vehicle not listed" path gives feedback guidance without transmitting any personal data off the browser (INV-4, INV-26) and does not open a mailto: or third-party form.
- FR-20: The picker does not render, and does not accept input, while `local_state == :hydrating`; interactive controls MUST NOT accept input before the hydration state is known (INV-24.3, §9 TTI). While `local_state == :storage_unavailable`, the picker renders in read-only/browse-only mode: the user may cascade and search but cannot commit, and the copy defined by [DOS-M09-004](DOS-M09-004.md) explains that nothing is being saved.

## Technical implementation contract

### Components and ownership boundaries

- `VehiclePickerLive` orchestrates the cascade and search over the hosted LiveView socket; `CascadeSelect` renders each dependent selector; `SourceBadge` renders coverage/support status; shared skeleton/pending/failure/reconnect/throttled/unavailable components come from [DOS-M09-004](DOS-M09-004.md) and the [DOS-M02-002](DOS-M02-002.md) design system.
- All catalog reads go through `DigitalOilSticker.Catalog`, which delegates to the [DOS-M09-005](DOS-M09-005.md) read-only query layer. The LiveView never imports `CatalogRepo`, composes SQL, or opens a database (ADR-0004 Decision §6 static enforcement).
- The commit action calls `Garage.save_vehicle/2` (through the [DOS-M05-001](DOS-M05-001.md) API); `Garage` initiates the [DOS-M09-003](DOS-M09-003.md) mutation round trip against the browser `vehicles` object store. The picker owns no persistence and never writes IndexedDB directly.
- The `LocalStore` JS hook is not authored here; the picker relies on the [DOS-M09-002](DOS-M09-002.md) hook and the [DOS-M09-003](DOS-M09-003.md) protocol.

### Data and persistence

- Server-side catalog reads target the read-only `CatalogRepo` opened by the deployed application (ADR-0004 Decision §4); the picker never opens a Repo, and there is no `UserRepo` in the deployment (INV-23).
- Committed vehicle rows are written by the [DOS-M09-002](DOS-M09-002.md) adapter into the IndexedDB `vehicles` object store defined by [DOS-M09-001](DOS-M09-001.md); each row carries the stable `configuration_key`, catalog `data_version`, support status, and readable display snapshot so history remains understandable after a Fly release changes the catalog. There is no cross-database foreign key: catalog references are resolved at render time against the current `data_version` and MAY come back `unsupported` if the version moved — a legitimate INV-11 state, rendered as such.
- No server-side row is written by this card in any code path (INV-3, INV-23, ADR-0004 Enforcement).

### Interfaces and events

- Catalog query functions on `DigitalOilSticker.Catalog` (delegating to [DOS-M09-005](DOS-M09-005.md)): years available, makes for year, models for (year, make), variant/configuration rows for (year, make, model), and normalized text search — each returning stable IDs plus display/provenance fields and completeness codes, plus the response envelope's `data_version` for the stale-selection check in FR-14.
- The commit action publishes `vehicle_saved` **after** the [DOS-M09-003](DOS-M09-003.md) hook `local_store:ack` is received, carrying local stable IDs and reason codes (never display strings) per [DOS-M05-001](DOS-M05-001.md) FR-5.
- Debounced `phx-change`/`phx-keyup` search events with server-side paging; result pages carry a total-count value for the accessible announcement. Debounce interval and page size are documented alongside the performance evidence (Risks & decisions).

### Failure and recovery behavior

- Catalog-query failure surfaces the FR-4 explicit state with retry; the picker never renders a partial or stale catalog page as authoritative.
- Per-socket rate-limit throttling from [DOS-M09-005](DOS-M09-005.md)/[DOS-M09-008](DOS-M09-008.md) surfaces the FR-5 throttled state.
- LiveView reconnect (network blip, deploy — ADR-0004 §"WebSocket and LiveView considerations") remounts, re-runs hydration through [DOS-M09-003](DOS-M09-003.md), and restores the picker without a partial commit; the disconnect is rendered via `phx-disconnected` styling, not a torn-down skeleton.
- A stale-catalog selection at commit (FR-14) returns the stale-selection error and restarts the affected cascade level.
- A missing hook `local_store:ack` at commit (FR-16) renders the persistent "Not saved to this browser" state.
- A `QuotaExceededError` at commit (FR-17) renders the quota-specific message and offers export.

### Security and privacy

- Every catalog request payload is auditable and MUST NOT contain any personal field (INV-4, INV-26); see AC-9 and the [DOS-M07-003](DOS-M07-003.md) / [DOS-M09-008](DOS-M09-008.md) idle-traffic and payload audits.
- Search input is user text: normalized on the server, parameterized in the [DOS-M09-005](DOS-M09-005.md) queries, and never logged verbatim (server logging redaction is owned by [DOS-M09-008](DOS-M09-008.md); this card MUST NOT introduce a log line that carries the raw search string, the selected `configuration_key`, or the vehicle's display text).
- CSRF: the LiveView socket join carries the framework `_csrf_token` per ADR-0004 §"CSRF and session"; `check_origin` is the [DOS-M09-008](DOS-M09-008.md)-configured explicit host list.
- No third-party origin is contacted by the picker (INV-4, INV-22).

### Accessibility and performance

- WCAG 2.2 AA per §9: full keyboard operability with visible focus, no keyboard trap, target size ≥ 24×24 CSS px (≥ 44×44 SHOULD where touch is primary), 200% zoom and 320 CSS px reflow, live-region announcement of result-count changes without stealing focus.
- First cascade page and first search page meet the ratified §9 `catalog query p95` and `LiveView event round trip p95` budgets, measured on the deployed Fly.io environment; the void 1.0.0 loopback budgets are not used (§9 R9). Measurement is against the full-size catalog artifact from [DOS-M09-006](DOS-M09-006.md) or the deterministic fixture from [DOS-M01-004](DOS-M01-004.md).

## UX and content states

- **Pre-hydration.** Only the [DOS-M09-004](DOS-M09-004.md) skeleton is rendered; no cascade, no search input, no empty-garage claim (INV-24.3).
- **Storage-unavailable.** The [DOS-M09-004](DOS-M09-004.md) session-only banner is rendered above the picker; the picker functions as read-only/browse-only, with commit disabled and the honest copy from INV-25 (INV-24.6).
- **Cascade per level.** loading (pending query), populated, narrowed-empty (an upstream choice eliminated all options — distinguishable from a catalog-query failure), cleared-downstream after an upstream change.
- **Search.** idle with guidance, pending, results with accessible count announcement, no-result with the manual "vehicle not listed" guidance path.
- **Query-slow / query-failed / throttled / socket-down.** four visually distinct states with distinct copy: slow (still trying), failed (bounded retry offered, prior valid state preserved), throttled (paused until the window elapses, honest reason), socket-down (`phx-disconnected` styling; interactions deferred until reconnect). None of them is rendered as `:empty` (INV-24.3, INV-7).
- **Result rows.** full disambiguation fields; unknown attributes render "Not specified" (INV-21); coverage/support status badge (`identity_only`, `schedule_supported`, `full_product_supported`, `not_applicable`, `unsupported`) with the [DOS-M02-002](DOS-M02-002.md) reviewed wording.
- **Review state.** selected identity summary, the statement that recommendations depend on exact configuration, precision label for broad mappings, back navigation that preserves prior valid choices, and the explicit confirm action.
- **Commit-in-flight.** the "saving" affordance from [DOS-M09-003](DOS-M09-003.md), rendered until `local_store:ack` arrives; on ack-timeout the persistent "Not saved to this browser" state (FR-16); on `QuotaExceededError` the quota-specific message with export offered (FR-17).
- **Post-commit / multi-tab.** the "reloaded from this browser's newer data" notice per FR-15 when a sibling tab's commit arrives.
- **Terminology.** "Stored in this browser" for anything relating to the committed vehicle (INV-21); "saved to your account", "synced", "backed up", "restore" are prohibited.

## Rollout and rollback

Ships as part of the normal hosted deploy pipeline ([DOS-M09-006](DOS-M09-006.md)): a new image containing this picker is deployed to Fly with the ratified rollout strategy; readiness gates the transition. A deploy drops every LiveView socket, and every affected client remounts and re-runs [DOS-M09-003](DOS-M09-003.md) hydration; a picker interaction in flight at deploy time is deferred until reconnect and re-runs against fresh assigns (ADR-0004 §"WebSocket and LiveView considerations"). ## Dependency rationale

- [DOS-M09-005](DOS-M09-005.md) is the load-bearing precondition: it is the only path by which this card reaches catalog data (ADR-0004 Decisions §2 and §4). Without it the picker cannot render a single option.
- [DOS-M09-003](DOS-M09-003.md) is the only mechanism by which the committed selection reaches durable client storage; committing outside its mutation round trip would either write server-side (violating INV-3/INV-23) or silently bypass the multi-tab and failed-ack disciplines (violating INV-24.2/24.5/24.7).
- [DOS-M09-001](DOS-M09-001.md), [DOS-M09-002](DOS-M09-002.md), and [DOS-M09-004](DOS-M09-004.md) supply the `vehicles` store, the typed adapter, and the pre-hydration/storage-unavailable UX vocabulary this card renders around.
- [DOS-M05-001](DOS-M05-001.md) (rescoped) wires the browser-first `Catalog` and `Garage` contexts; committing a selection without it would force LiveView-owned persistence, which is prohibited.
- [DOS-M02-002](DOS-M02-002.md) / [DOS-M02-004](DOS-M02-004.md) supply the browser-MVP design system, WCAG contract, and picker copy; [DOS-M07-003](DOS-M07-003.md) supplies the ratified performance budgets that replace the void 1.0.0 loopback budgets.
- This card unblocks [DOS-M05-003](DOS-M05-003.md) (create/edit vehicle continues the committed selection through the same mutation protocol) and [DOS-M05-005](DOS-M05-005.md) (dashboard identity rendering).
- The pre-pivot dependency on a validated **bundled** catalog is retired; the equivalent obligation is that the deployed [DOS-M09-006](DOS-M09-006.md) image carries a verified `data_version` (ADR-0004 §"Catalog database on Fly").

## Risks, decisions, and open questions

- **Risk (R2 in ADR-0004):** hydration adds latency to first meaningful paint on every mount and every reconnect. If hydration exceeds the §9 target the picker's TTI budget is at risk. Mitigation: this card renders only after `local_state` is `:loaded`/`:empty`; the pending state is honest (FR-20).
- **Risk (R9 in ADR-0004):** §9 latency budgets are provisional and re-ratify on measurement against the deployed environment. This card measures against the ratified values at test time and MUST NOT ship against known-void 1.0.0 loopback numbers.
- **Risk (R1 in ADR-0004):** browser storage eviction of infrequently-used origins. Mitigation is [DOS-M09-004](DOS-M09-004.md)'s `:data_missing` copy and the [DOS-M09-002](DOS-M09-002.md) persistence probe; this card's job is to route the returning user through the picker without ever presenting an evicted store as a fresh install (AC-2).
- **Risk (R7 in ADR-0004):** catalog endpoints are publicly scrapable. Mitigation is the [DOS-M09-008](DOS-M09-008.md) per-socket rate limit and this card's FR-5 throttled-state contract; a well-behaved picker MUST NOT itself become a scraper by retry-storming.
- **Risk (INV-24.1 semantics):** the pre-pivot "airplane-mode journey" is a promise this architecture cannot keep. Retiring it (not replacing it with a weaker offline claim) is the honest disposition per ADR-0004 §"Consequences → Lost — honestly" and INV-19.
- **Decision to record:** exact debounce interval and page size, documented alongside the performance trace and cross-checked against the [DOS-M09-008](DOS-M09-008.md) per-socket rate-limit ceiling.
- **Decision to record:** the exact retry backoff and cap for FR-4, aligned with [DOS-M09-008](DOS-M09-008.md) and validated in AC-7.
- **Open question:** whether text search uses server-side FTS — allowed only if the [DOS-M09-005](DOS-M09-005.md) query layer admits it; the indexed non-FTS path is mandatory either way.
- **Open question:** whether the read-only "newer data" mode arriving on a rollback (ADR-0004 §"Schema versioning and migration") requires this card to render a dedicated commit-disabled state distinct from `:storage_unavailable`. Defer until [DOS-M09-004](DOS-M09-004.md) fixes the shared copy.

## Superseded pre-pivot spec (historical record)

### Outcome (superseded)

A user can find an exact supported year/make/model/variant from the installed catalog and commit it to the single-vehicle profile entirely offline.

### Why this matters and what it unblocks (superseded)

The dashboard, interval lookup, service record, and forecast cannot be trusted until an exact, catalog-backed vehicle identity is selected. Recommendation fidelity (§3 rule 4: no fabricated automotive facts; rule 5: requirements, not brand folklore) begins at selection: an ambiguous or guessed vehicle poisons every downstream sourced claim. This issue blocks DOS-M05-003 (the selected configuration becomes the local profile) and DOS-M05-005 (the dashboard renders the selected identity).

### Context and source of truth (superseded)

- Master roadmap prompt (`digital-oil-sticker-claude-code-roadmap-prompt.md`), §11.3 catalog entry "DOS-M05-002 — Build offline exact-vehicle search and selection".
- §3 rule 2 (offline from first launch: every selector works offline with a clear no-result/manual path) and rule 4 (missing data shown as unknown, never guessed).
- §5 Frozen scope boundaries: one active vehicle selected by year, make, model, and best available licensed configuration; manual fallback when exact configuration is unavailable; support statuses `identity_only`, `schedule_supported`, `full_product_supported`, `not_applicable`, `unsupported`.
- §6 User and content contract, journey step 2 (year → make → model → available configuration, offline, with no-result/manual path) and step 3 (confirm/manual-enter instead of guessing).
- §8 `CatalogRepo` baseline: `makes`, `models`, `vehicle_configurations` (stable `configuration_key`, completeness code, search text, indexes), `aliases`, and the rule that cascading indexed selectors must work without FTS.
- §7 expected components: `VehiclePickerLive`, `CascadeSelect`, `SourceBadge`, `OfflineState`, and consistent empty/error states.
- DOS-M05-001 context APIs and fixtures; the M02 UX/content contract for picker copy; the DOS-M07-003 performance budget it must meet.

### Included (superseded)

- Progressive filters in the order Year → Make → Model → Variant/trim/body/engine when those dimensions exist, each choice narrowing valid subsequent choices.
- Text search over the installed catalog with normalization of case, whitespace, punctuation, and documented aliases.
- Result disambiguation display: enough sourced fields to prevent ambiguous selection.
- No-result paths for every filter level and for text search.

- Precision labeling when only a broad vehicle mapping exists.

- Fuzzy guesses that auto-select.

- Multiple saved vehicles.

### Preconditions (superseded)

### Functional requirements (superseded)

- FR-1: Query only the locally installed, validated SQLite catalog through a read context. No network request is issued by any search, filter, or selection interaction.
- FR-2: Debounce expensive LiveView search events and page results so the on-device Endpoint/WebView remains responsive.
- FR-3: Use stable catalog IDs, never display strings, as foreign keys throughout filter state, results, and the committed selection.
- FR-4: Filter order is Year → Make → Model → Variant/trim/body/engine when those dimensions exist. Each choice narrows valid subsequent choices and clears incompatible downstream selections.
- FR-5: Search normalizes case, whitespace, punctuation, and documented aliases but never collapses distinct engines or variants.
- FR-6: Results display enough fields to prevent ambiguous selection: model year, make, model, variant/trim, engine displacement/cylinders/fuel when sourced, drivetrain/body when needed, and source-data coverage status. Unknown is shown as "Not specified," never guessed.
- FR-7: The final review states that recommendations depend on exact configuration and lets the user go back without losing prior valid choices. If only a broad vehicle mapping exists, the selection carries a visible precision label.
- FR-8: Search/filter state is disposable; a vehicle profile is written only after explicit confirmation (via the DOS-M05-001 `Garage` API). Back navigation and app termination before confirmation create no partial profile.
- FR-9: A result cannot be committed without all catalog-required disambiguating fields.
- FR-10: All controls are keyboard/screen-reader operable, have visible labels, preserve 44×44 CSS-pixel touch targets, and announce result-count changes without stealing focus.

### Technical implementation contract (superseded)

#### Components and ownership boundaries

- `VehiclePickerLive` orchestrates the cascade and search; `CascadeSelect` renders each dependent selector; `SourceBadge` renders coverage/support status; shared empty/error/offline components come from §7.
- All catalog queries go through the `DigitalOilSticker.Catalog` read context established in DOS-M05-001; the LiveView holds only disposable UI state and stable IDs.
- The commit action calls `Garage` (DOS-M05-001) with the selected `configuration_key`; the picker owns no persistence.

#### Data and persistence

- Reads target `CatalogRepo` tables from §8: `makes`, `models`, `vehicle_configurations` (indexed `(model_year, make_id, model_id)` and provider key), and `aliases` (unique alias within entity type, indexed for lookup).
- Cascading selectors use the indexed columns and must work without FTS; optional FTS tables are used only if the earlier Mob/exqlite proof admitted them (§8).
- Nothing is written by this feature except the final confirmed profile through `Garage`; no search history or partial selection is persisted.

#### Interfaces and events

- Context query functions: years available, makes for year, models for (year, make), variant/configuration rows for (year, make, model), and normalized text search — all returning stable IDs plus display/provenance fields and completeness codes.
- Committing the selection triggers the `vehicle_saved` event via the DOS-M05-001 contract; the picker itself publishes no events.
- Debounced `phx-change`/`phx-keyup` search events with server-side paging; result pages carry a total-count value for the accessible announcement.

#### Failure and recovery behavior

- Catalog-unavailable or corruption surfaces the DOS-M05-001 typed error state with recovery guidance; the picker never renders a partial catalog silently.
- A selection that becomes stale before commit (catalog replaced mid-flow) returns the controlled stale-selection error from DOS-M05-001 rather than committing a dangling reference.
- LiveView reconnect during search restores a usable picker; because filter state is disposable, a lost socket at worst restarts the cascade without a partial profile.

#### Security and privacy

- Entirely offline: no network search, no telemetry, no transmission of "vehicle not listed" feedback; the offline network log evidence must show zero non-loopback traffic during the whole journey.
- Search input is user text: normalized locally, parameterized in queries, never logged verbatim (fixtures/logs redact per §7).

#### Accessibility and performance

- Keyboard and screen-reader operability for every filter, search field, result row, and the review/commit step; visible labels; 44×44 CSS-pixel touch targets; result-count changes announced politely without stealing focus.
- Search remains responsive under the maximum supported bundled catalog; first result page returns within the performance budget defined in DOS-M07-003, measured with the full-size fixture catalog.
