> **RESCOPED FOR BROWSER MVP — 2026-08-01.** [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) established the browser-first MVP. This card is retained with the same identity; its Outcome and FRs below are the rescoped spec. The pre-pivot spec is preserved at the bottom under "Superseded pre-pivot spec (historical record)". Disposition per [PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md](../../docs/governance/PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md#issue-by-issue-classification): _Store release becomes public web launch on the custom domain; the hardening and closed-beta structure carries over._

## Outcome

The hosted Phoenix LiveView application is accessible, private, secure, supportable, performant, migration-safe, and demonstrably reliable across the declared browser/engine/OS matrix. Signed and attested container images, `digitaloilsticker.com` custom-domain cutover, staged Fly.io deploys, canary smoke, and a rehearsed rollback take the app from an unlisted staging hostname through a privacy-preserving invite-only beta into a stable public web launch — with no accounts, no server-side personal record, and no behavioral telemetry.

## Why this matters and what it unblocks

M05 and M06 (as rescoped by the 2026-08-01 pivot) deliver a functionally complete single-vehicle browser MVP: hosted Phoenix LiveView on Fly.io, anonymous IndexedDB user storage, catalog-served-from-server, and in-app due/overdue state in lieu of OS notifications. "Functionally complete" is still not "publicly launchable." M07 converts working software into a shippable hosted product: it proves the privacy promises the product makes about a *public* internet-facing server (transient assigns only, no personal-data tables, redacted logs, no third-party trackers — INV-3, INV-4, INV-22, INV-26), certifies WCAG 2.2 AA conformance across a named browser and assistive-technology matrix (including keyboard-only desktop use the mobile bar never covered), enforces browser-appropriate performance budgets (page load, time-to-hydrated, LiveView round-trip latency, server memory per socket, IndexedDB footprint) against the hosted architecture, executes the cross-browser QA matrix with storage-eviction/quota/private-browsing/multi-tab/reconnect rows added, hardens CI and the supply chain so release artifacts are signed and attested container images with reproducible provenance and an immutable Fly release identifier, runs a privacy-preserving invite-only closed beta on an unlisted staging hostname, and stages the production cutover to `digitaloilsticker.com` with canary smoke and a rehearsed one-command rollback. This epic is the launch gate for the browser MVP and the baseline that M09 (hosted browser platform hardening) and M08/M10 post-MVP work build on. No M08/M09/M10 work may begin against an unreleased, unhardened hosted baseline.

## Included

Child issues tracked by this epic (each will carry its own rescoped body):

- `DOS-M07-001` — Threat-model the hosted, internet-facing privacy boundary: a public-web threat model covering socket/origin abuse, CSRF, transient personal data in assigns, log and error-report redaction, session-cookie constraints, rate limiting, and a *tested* guarantee that no personal-data table exists in the deployed schema and that VIN / odometer / date / note / vehicle-name values never reach logs or error reports.
- `DOS-M07-002` — WCAG 2.2 AA release bar across a named browser and assistive-technology matrix: keyboard-only desktop use, screen readers (NVDA/JAWS on Windows, VoiceOver on macOS/iOS Safari, TalkBack on Android Chrome), large text, contrast, reduced motion, focus order, and target-size certification of every critical LiveView workflow.
- `DOS-M07-003` — Page-load, time-to-hydrated, LiveView round-trip, server memory-per-socket, and IndexedDB footprint budgets, measured against a hosted `ord` deploy from the geographies in the support matrix, with the constitution §9 replacement budgets recorded as they are re-ratified.
- `DOS-M07-004` — Cross-browser / engine / OS QA matrix: risk-based browser/engine/OS coverage plus storage-eviction, quota, private-browsing, multi-tab, reconnect-during-deploy, and export/import round-trip rows. Notification rows are removed (there is nothing scheduled to reconcile).
- `DOS-M07-005` — CI, supply-chain, and signed-and-attested container image gates: PRs and release tags cannot produce a deployable Fly image without repeatable quality/security checks across BEAM code, assets, SBOM/dependency review, secret-scan, container base-image provenance, and image signing with an immutable Fly release identifier bound to the git SHA and catalog artifact hash.
- `DOS-M07-006` — Privacy-preserving invite-only closed beta on an unlisted staging hostname (or invite link), with defect intake that MUST NOT collect browser-storage contents. Feedback and diagnostics are explicit, minimal, and actionable; the intake form and any beta email templates are copy-reviewed against INV-5/INV-25.
- `DOS-M07-007` — Prepare, stage, monitor, and recover the hosted release: staged Fly deploys, `digitaloilsticker.com` cutover from the staging hostname, canary smoke on the production hostname, live-signal monitoring, and a rehearsed one-command Fly rollback that returns the previous signed image and its baked-in catalog artifact.

### Components and ownership boundaries

N/A — epic-level tracking issue. ### Data and persistence

N/A — epic-level tracking issue. The deployed application has exactly one Ecto repo, `DigitalOilSticker.CatalogRepo`, opened **read-only**, per ADR-0004 §4. There is no `UserRepo` in the deployment. Personal data lives in anonymous IndexedDB (`dos_local`) in the user's browser and, transiently, in `socket.assigns` for the lifetime of one LiveView connection, per INV-23 and INV-24. No child may introduce a server-side personal-data table, cache, ETS store, external store, or persistent log line — this is enforced mechanically by the FR-6 tests, not by convention.

### Interfaces and events

N/A — epic-level tracking issue. Children exercise existing contracts (the LiveView hydration protocol specified in ADR-0004 §"The client-storage + LiveView hydration protocol" — `local_store:hydrate`, `local_store:put`, `local_store:ack`, `local_store:conflict`; the read-only `CatalogRepo` query surface delivered by `DOS-M09-005`; and export/import driven entirely in the hook), rather than adding new ones. Any new event or endpoint proposed by a child is out of scope for M07 and belongs in M09 or later.

### Failure and recovery behavior

N/A — epic-level tracking issue. Failure-mode proof is the substance of `DOS-M07-004` (matrix, including storage eviction / quota / private browsing / multi-tab / reconnect) and `DOS-M07-007` (canary halt, forward-fix, Fly rollback of the signed image and its baked-in catalog, honest guidance for users whose browser storage was cleared). The recovery story for personal data is export/import — the *only* recovery path per INV-5/INV-25 — and children may not imply otherwise.

### Security and privacy

The epic enforces, via its exit gate, that no child weakens the hosted security baseline recorded in ADR-0004 §"Security and privacy boundary for a hosted application" and INV-22: HTTPS/WSS only with `force_ssl` and HSTS-after-verification, `check_origin` restricted to the exact production hostnames, `protect_from_forgery` on HTTP routes with LiveView `_csrf_token` verified on connect, a signed `same_site: "Lax"` session cookie that carries no personal data and no stable user identifier, the CSP recorded in ADR-0004, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, and a `Permissions-Policy` denying geolocation/camera/microphone/payment. LiveDashboard is disabled in production; the operator-access honesty statement (ADR-0004 §"LiveDashboard and operator access — stated honestly") is reflected in the privacy page copy. Logging follows the MAY/MUST NOT list in ADR-0004 §"Logging"; `debug_errors: false` in production.

### Accessibility and performance

The epic enforces, via its exit gate, the `DOS-M07-002` WCAG 2.2 AA browser/AT matrix and the `DOS-M07-003` browser-appropriate performance budgets (page load, time-to-hydrated, LiveView round-trip latency, server memory-per-socket, IndexedDB footprint), measured against the hosted `ord` deploy from the geographies in the support matrix. Regressions in either dimension are release blockers. The §9 latency budgets that ADR-0004 recorded as void are re-measured and re-ratified as they are proven — no ship against known-inapplicable budgets.

## Risks, decisions, and open questions

- Risk: **Browser eviction of infrequently-used site storage** (ADR-0004 R1) is the single biggest product risk of the pivot and lands squarely on the M07 launch surface. Mitigations under M07: `DOS-M07-002`/`003`/`004` measure and honestly render the eviction/quota/persist-grant state, `DOS-M07-006` beta feedback tracks actual loss reports, and the release-approval record (FR-8) names this risk explicitly rather than treating it as solved.
- Risk: **`digitaloilsticker.com` cutover** is a DNS + TLS + HSTS event; HSTS is enabled only after certificate verification per ADR-0004 to avoid self-inflicted downtime. Rehearse against the staging hostname first; do not request `preload` at MVP.
- Risk: **Deploys drop WebSockets** (single machine at MVP, ADR-0004 R8). Reconnect + re-hydration must be proven robust enough (FR-5) that a deploy is a non-event for users; a second always-on machine is a bounded cost decision revisited on real usage.
- Risk: **The strict CSP is unverified against LiveView's full runtime behavior** (ADR-0004 R3). If a nonce plug is required to preserve the CSP without `'unsafe-inline'`, that surfaces in `DOS-M07-005` release gates rather than at cutover.
- Risk: **Whether users accept a product that does nothing offline and never notifies them** (ADR-0004 R11) is the core product bet of the pivot. `DOS-M07-006` is the first structured chance to see the answer; the release-approval record names this residual risk.
- Risk: **Web-serving rights for licensed catalog sources are a hard gate** (ADR-0004 R6). Precondition, not a launch-day discovery: any documented-facts or permission-needed source without web-serving rights is not served by the launched app.
- Decision (recorded per child): hosted privacy boundary and posture (`DOS-M07-001`), browser/AT support matrix and Tier-1 combinations (`DOS-M07-002`/`004`), performance-budget replacements and waivers (`DOS-M07-003`), invite-only staging hostname vs. invite-link mechanism (`DOS-M07-006`), staged Fly deploy sequence and cutover window (`DOS-M07-007`).
- Open question: none at epic level; child open questions are tracked in their own sections.
