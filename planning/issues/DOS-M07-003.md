> **RESCOPED FOR BROWSER MVP — 2026-08-01.** [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) established the browser-first MVP. This card is retained with the same identity; its Outcome and FRs below are the rescoped spec. The pre-pivot spec is preserved at the bottom under "Superseded pre-pivot spec (historical record)". Disposition per [PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md](../../docs/governance/PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md#issue-by-issue-classification): _Battery and native-memory budgets are replaced by page-load, time-to-hydrated, LiveView round-trip latency, server memory-per-socket, and IndexedDB footprint budgets._

## Outcome

The hosted Phoenix LiveView browser MVP — served from Fly.io at `digitaloilsticker.com`, with all personal data in anonymous IndexedDB and no server-side personal record — meets a *provisional*, measured, and re-ratifiable set of budgets that describe how the product actually behaves for real users on the public internet. Every budget in Constitution 2.0.0 §9 that applies to this issue has an owner, a baseline number produced by a repeatable command on the deployed Fly environment (not a laptop, not a loopback, not an emulator), a fail/warn threshold wired into CI comparison, and a documented re-ratification path when the *provisional* label is lifted. The retired 1.0.0 rows — cold tap-to-interactive, warm start, on-device Phoenix readiness, packaged app size, bundled catalog size, minimum supported OS, and airplane-mode offline readiness — are not silently missed and not silently re-baselined: they are recorded here as removed, with the browser-first replacements named below.

## Why this matters and what it unblocks

The pre-pivot budget register was written for an embedded-BEAM-in-Mob-WebView architecture whose endpoint was `http://127.0.0.1:4000` and whose delivery vehicle was a signed native package with a bundled starter catalog. ADR-0004 voided both premises. Its "Consequences" section is explicit: *"Constitution §9's latency and size budgets are void. The interaction-latency budget (local p95 ≤ 100 ms) was written for a loopback socket and is not achievable coast-to-coast over the public internet. New provisional budgets must be measured and re-ratified rather than quietly missed. Packaged-app-size budgets are replaced by a first-paint payload budget."* Its risk R9 records the same obligation: measure real-world p50/p95 by geography, propose provisional budgets, do not ship against budgets known to be inapplicable. Constitution 2.0.0 §9 already installs the replacement rows and marks them *provisional*; this issue is the harness, the measurement, the CI comparison, and the evidence that turns those rows from placeholders into a release gate.

Without this issue, three failure modes are structurally invited. First, a first-visit payload that quietly grows past ADR-0004's "no third-party origins, first-party bundled" posture and starts to feel like a heavy web app — the exact impression the pivot exists to avoid. Second, a hydration path (INV-24) that is fast in developer testing on `localhost` and slow in Chicago-to-coast production, so returning users watch a skeleton for longer than they will tolerate. Third, a per-socket server memory footprint that scales badly with concurrent users on the single always-on `ord` machine ADR-0004 chose, forcing a cost decision as an incident rather than as a plan.

This issue unblocks the re-scoped `DOS-M07-004` (browser/engine matrix runs against a budget-verified deploy and shares the browser-support matrix from CONSTITUTION §9), the re-scoped `DOS-M07-007` (public-web release evidence includes the performance baseline and any exception ADRs), and the re-scoped `DOS-M07-005` (the CI comparison for release-candidate builds runs alongside signed/attested-image gates on the same pipeline). It consumes the deploy pipeline and release identifier from `DOS-M09-005`, the browser support matrix from `DOS-M09-008`, and the storage-behavior conformance evidence produced by that same suite.

## Included

- The **budget register** for the hosted browser MVP: every §9 row that measures a runtime property of the deployed Fly application has an owner, a *provisional*-or-ratified baseline, a repeatable measurement command, and a fail/warn threshold. Rows are versioned alongside the constitution and are re-baselined only by explicit re-ratification.
- **Page-load measurement** on the deployed Fly application from at least three US geographies (a near-region client in the Midwest, an East-coast client, and a West-coast client) on a mid-tier mobile device profile over a 4G-class throttled network: LCP p75, TTI / first-interaction-ready p75, worst run.
- **LiveView WebSocket connect** measurement (static-to-live transition after HTML paint; automatic reconnect after an induced disconnect) from the same geographies, with reconnect explicitly re-running hydration (INV-7, INV-24).
- **Hydration completion** measurement — the time from LiveView socket join to `local_state == :loaded` (or an explicit failure state) — measured client-side, correlated with a server-side span, and asserted against the *provisional* p95 ≤ 300 ms row.
- **LiveView event round-trip latency** measurement — an impersonal navigation/filter event from the client, hitting the server, returning a rendered diff — measured from the client per geography.
- **Server response p95** measurement — HTTP TTFB and event round-trip — measured from the client and cross-referenced with server-side spans from an origin-only telemetry sink that never leaves the application origin (INV-4/INV-22).
- **Catalog query p95** measurement — first paged result and subsequent filter — measured with the read-only server-side query layer (`DOS-M09-005`'s consumer) and asserted against §9. Every measured query is an impersonal query (INV-26).
- **First-visit and repeat-visit payload budgets** — measured over the wire against the *provisional* 250 KiB / 500 KiB / 60 KiB targets and against the **zero third-party origins** rule (INV-22). Includes a build-time asset accounting step and a runtime capture step; the two must agree.
- **Server memory-per-socket** measurement — steady-state per-connection resident-memory footprint on the always-on Fly machine, sampled during a synthetic concurrent-connection soak, with a computed capacity ceiling per current VM size. This is what replaces the retired on-device memory row for the purpose of sizing Fly VMs (ADR-0004 "Cost shape").
- **IndexedDB footprint budget** — measured on the browser-support matrix's supported browsers with synthetic fixtures scaled to 1,000, 5,000, and 10,000 records against the ≤ 1 MiB per 1,000 records target and the 5 MiB working ceiling, with quota-exceeded behavior asserted per **INV-24.5**.
- **Deploy-survivability rehearsal** — a scripted rehearsal that deploys while sessions are live (idle; mid-selection; with an unacknowledged mutation in flight), asserting no user data loss, no false empty-garage frame (INV-24.3), correct pending-write re-drive from client storage, and that reconnect + re-hydration meets the LiveView-reconnect budget (ADR-0004 R8). This is a performance-measurement rehearsal for the reconnect budget; the underlying deploy contract lives in `DOS-M09-005`.
- **CI performance-comparison job** — runs the repeatable measurement commands against the current release candidate (identified by the `DOS-M09-005` release identifier), compares against the last ratified baseline, and applies fail/warn thresholds per row.
- **Origin-only measurement sink** — a first-party endpoint on the application origin that receives synthetic-run measurements from the harness only, aggregated by release identifier and geography, with no personal field ever transmitted (INV-4/INV-22/INV-26). This is not production telemetry from real users.
- **Budget-change control documentation** — how a *provisional* value is re-ratified (constitution-revision path per CHANGE_CONTROL Rule 2a), and how an accepted budget exception is recorded (ADR with user impact, mitigation, owner, and target release).

## Excluded

This issue does not measure them, does not restore them, and does not silently substitute for them; they are recorded as removed in §9 and belong to the deferred native re-entry (INV-1).

INV-4 and INV-22 forbid a third-party origin, and INV-3/INV-23 forbid a server-side personal record — a per-user performance stream is a per-user record in disguise. All measurements in this issue are synthetic runs on the harness against the deployed environment.
- The Fly.io deploy pipeline, `fly.toml`, region selection, readiness endpoint, secret handling, and rollback command — `DOS-M09-005`. This issue consumes the release identifier and rehearses reconnect performance during a deploy; it does not build the pipeline.
- CSP contents, `check_origin` host list, CSRF configuration, rate-limit thresholds, and log-redaction filters — the M09 internet-facing hardening issue. This issue must not weaken any of them and measures inside their constraints.
- The browser support matrix contents and the storage-behavior conformance suite — `DOS-M09-008` owns the matrix and the eviction/quota/private-mode/multi-tab tests. This issue consumes both and applies the storage-footprint budget across the matrix.
- Pre-hydration copy, storage-loss states, and the honest-degradation screens — `DOS-M09-003` (and its downstream re-scoped `DOS-M02-003` / `DOS-M05-005` / `DOS-M05-007`). This issue verifies the *performance* of those states (the honest-degradation-coverage row) and shares evidence, but does not author the copy.
- Custom domain and TLS setup, HSTS enablement, canonical redirects, and the Fly/Netlify content boundary (INV-27) — the M09 domain-and-TLS issue.
- Premature micro-optimization without a trace. An optimization PR under this budget must cite the trace and the affected row.

## Technical implementation contract

### Components and ownership boundaries

- Measurement harness, origin-only measurement sink, and CI performance-comparison job: owned by this issue (QA / Browser Delivery & Hosted Transport workstream). Produces the repeatable commands and the release-identifier-keyed measurement dataset consumed by `DOS-M07-005` (signed/attested-image gates) and `DOS-M07-007` (public-web launch evidence).
- Optimization changes: applied in the owning modules (server-side catalog queries in `DigitalOilSticker.Catalog`; forecast recompute in `DigitalOilSticker.Forecasting`/`Maintenance`; LiveView assigns, diff shape, and JS-hook payloads in the UI layer; asset build in the esbuild/Tailwind pipeline) as reviewed PRs under the sibling issues that own those surfaces. This issue defines the budgets; the owning workstream fixes its own regressions.
- Browser support matrix and storage-behavior conformance suite: owned by `DOS-M09-008`. This issue applies §9 budgets across the matrix and does not extend it.
- Deploy pipeline, release identifier, readiness endpoint, and rollback command: owned by `DOS-M09-005`. This issue reads the release identifier as measurement metadata.
- Budget-change control: a *provisional* value becomes a ratified value by a constitution revision under CHANGE_CONTROL Rule 2a; an accepted budget exception requires an ADR (FR-9).

### Data and persistence

- **No personal data in any measurement.** Every synthetic fixture used for hydration, mutation, catalog query, and IndexedDB footprint measurement is generated from a deterministic seed, contains no real VIN, no real odometer reading, no real service date, and no free-text field with plausible identity content. The seed and the generated payload are checked in as test data (INV-3, INV-4).
- **Synthetic client-storage fixtures** at 1,000 / 5,000 / 10,000 records scale, produced through the same client-side write path a real user would take (via `DOS-M09-001`'s storage adapter), so the measured footprint reflects the real object-store and index overhead — not a hand-shaped estimate.
- **Release identifier is the primary key** of every measurement row (image digest + git commit + application version + catalog `data_version` + client-storage `schema_version`, from `DOS-M09-005`), joined with browser × geography × VM size. The comparison job compares like-for-like.
- **Origin-only measurement sink** persists aggregate measurement rows only, keyed by release identifier and cell, with no client identifier, no IP, no cookie, and no user-agent-derived fingerprint beyond the browser/OS class already recorded by the matrix. The sink schema is subject to the same INV-3 / INV-23 test the application enjoys (no personal-data table).
- **Catalog artifact under test** is the exact `data_version` baked into the release image (ADR-0004 "Catalog database on Fly"; CHANGE_CONTROL Rule 6). A measurement never mutates the catalog and never sees a half-swapped catalog because the artifact is immutable per deploy.

### Interfaces and events

- **Measurement commands are the interface** — documented, repeatable invocations (a CI job step or scripted browser run) per §9 row, producing comparable numbers with fields for release identifier, browser, geography, VM size, and timestamp.
- **Origin-only sink endpoint** — a first-party POST endpoint on the application origin accepting an aggregate measurement row from the harness runner. It is behind the same CSRF and CSP the application uses; its payload schema is versioned; it validates and rate-limits like any external input.
- **No new user-visible domain events.** Hydration `local_state` transitions (`:hydrating` → `:loaded` / `:empty` / `:storage_unavailable` / `:data_missing`) are the ones the harness observes; they are already defined by INV-24 and implemented under `DOS-M09-003`.
- **CI comparison report** — a diff of the current release-candidate measurements against the last ratified baseline per cell, posted to the pull request or the release-ledger entry. Rows above the fail threshold block; rows above the warn threshold warn.

### Failure and recovery behavior

- A budget failure in CI produces a fail/warn per its threshold. An unexplained regression blocks the release. An accepted regression requires an ADR under FR-9.
- The **deploy-survivability rehearsal** (FR-10) is failure-injection by design: it induces a WebSocket disconnect via a Fly deploy or an equivalent proxy nudge and asserts the LiveView-reconnect budget, the honest-degradation-coverage row, and pending-write re-drive.
- A quota-exceeded write during the IndexedDB-footprint measurement (FR-5) MUST surface in the harness as a plain-language user-visible state, MUST preserve prior state, and MUST offer export (INV-24.5). A silent write failure fails the row outright.
- The origin-only measurement sink is not a critical path for the application: if it is unreachable or full, the harness records the failure locally and the CI job reports "no measurement recorded" rather than the run being silently dropped. The application MUST continue to render correctly with the sink offline.

### Security and privacy

- **INV-4 / INV-22 (no third-party origins).** The measurement path introduces no third-party APM, RUM, error-reporting, analytics, tag-manager, session-recorder, or CDN. The strict CSP (ADR-0004) forbids exactly this, and the payload budget gate (FR-3) enforces it at build time as well.
- **INV-3 / INV-23 (no server-side personal record).** No measurement carries a VIN, odometer, date, note, custom vehicle name, or stable client identifier. The origin-only sink has no personal-data table and is subject to the same schema-audit test the application uses.
- **INV-26 (impersonal catalog-query surface).** Every catalog-query measurement uses impersonal selectors. The harness fails the query-latency row if any recorded request carries a personal field.
- **Log-redaction inheritance.** The harness runs against the deployed application under its production logging and CSP — it does not weaken either. Anything the application would filter out of a log (LiveView `handle_event` params, hydration payloads, mutation deltas — see ADR-0004 "Logging") is filtered out of a harness-triggered log line too.
- **Operator access rules** (ADR-0004 "LiveDashboard and operator access") apply to the harness runner as much as to a human operator: no routine production console attach, no inspection of a live socket. The harness's session for reconnect and interaction budgets is a scripted synthetic session whose assigns are, by construction, the deterministic fixture.
- The 24-hour idle wire capture (FR-12) is privacy evidence as well as performance evidence and is shared with the re-scoped `DOS-M07-001` threat model and `DOS-M07-007` release disclosure.

## Test plan

### Automated

- **CI performance-comparison job**: runs the repeatable measurement commands against the release-candidate deploy, joins them by release identifier × browser × geography × VM size, compares against the last ratified baseline, and applies fail/warn thresholds. Runs on every release-candidate build.
- **Payload-budget assertions**: build-time asset accounting (initial HTML + CSS + JS ≤ 250 KiB compressed; total first-visit transfer ≤ 500 KiB; repeat-visit ≤ 60 KiB warm) and a runtime capture that must agree. Zero-third-party-origin static check on the built bundle and on the served response headers (CSP).
- **Server response and query assertions**: from the client and cross-referenced with server spans; HTTP TTFB p95 ≤ 400 ms; LiveView event round trip p95 ≤ 150 ms; catalog first-paged p95 ≤ 250 ms; subsequent filter p95 ≤ 150 ms; write + forecast recompute p95 ≤ 150 ms.
- **IndexedDB footprint measurement**: synthetic fixtures at 1,000 / 5,000 / 10,000 records on every browser in the support matrix, asserting the ≤ 1 MiB per 1,000 records target and the 5 MiB working ceiling, and asserting quota-exceeded surfaces as a visible state.
- **Server memory-per-socket soak**: scripted concurrent-connection ramp on a Fly machine at the ratified VM size, sampling per-connection resident memory idle and during interaction, computing the capacity ceiling and asserting no monotonic per-socket leak.
- **Reconnect-and-remount rehearsal**: induce a WebSocket disconnect via a deploy or proxy nudge; assert reconnect p95 ≤ 2.0 s, re-run of hydration (INV-7), and pending-write re-drive.
- **Origin-only measurement sink schema audit**: assert the sink has no personal-data table and no field that could carry a personal identifier, alongside the application's own INV-23 schema audit.

### Manual / browser matrix

- Multi-geography measurement on the deployed Fly application from at least three US client locations (near-region Midwest, East coast, West coast) on a mid-tier mobile device profile over a 4G-class throttled network, per browser in the support matrix (current and prior stable Chrome, Edge, Firefox, Safari on desktop; iOS Safari 16+ and Android Chrome).
- Storage-behavior verification jointly with `DOS-M09-008`: quota exhaustion, evicted-store, private-browsing, blocked-storage, and multi-tab paths — assert both the honest state and its budget row.
- 24-hour idle wire capture on a browser from the support matrix pointed at the deployed application origin, with a network-tap tool recording every request; assert zero outbound requests beyond the application origin and no personal field in any request.
- Scripted deploy rehearsal against a staging Fly application: run three concurrent scripted sessions (idle, mid-selection, unacknowledged-mutation), trigger a deploy via the `DOS-M09-005` command, and record reconnect behavior and pending-write re-drive per session.
- Post-upgrade run of the critical journey per browser after a client-storage schema-version migration, verifying no user-visible regression in the perf budgets.

## Rollout and rollback

## Risks, decisions, and open questions

- **Risk (ADR-0004 R9):** the *provisional* §9 numbers may not survive first measurement — this is exactly why they are marked *provisional*. The contract is measure, propose, re-ratify, then ship against ratified values. Missing a *provisional* row is a data point for re-ratification, not a permission slip to ship past it silently.
- **Risk (ADR-0004 R2):** hydration adds latency on every mount, including every reconnect. The hydration-completion budget (*provisional* p95 ≤ 300 ms) is tight by design so the skeleton state does not become the dominant impression of the product; if measurement shows it is not achievable, the ADR-approved path is a re-ratified value plus a plan (fewer IDB reads, batched writes, reduced payload), not a hidden regression.
- **Risk (ADR-0004 R1):** eviction is the biggest product risk of the pivot; the IndexedDB footprint budget is one of the levers that keeps quota a non-issue in practice. A footprint that outgrows the working ceiling is not a budget miss to accept — it re-opens `DOS-M09-009`'s PWA-install-as-durability-mitigation discussion, honestly.
- **Risk (ADR-0004 R8):** single region, single machine — a deploy drops all sockets. FR-10's rehearsal exists so this is a measured non-event rather than an incident.
- **Risk (ADR-0004 R10):** cost growth under real traffic or abuse is unmeasured. Server memory-per-socket (FR-4) is the harness's contribution: it feeds the cost-shape decision on when to add a second machine or step VM sizes.
- **Decision required:** the specific ratified Fly VM size at which server memory-per-socket is measured for the release. Recorded here so it is a named number, not a floating assumption; documented alongside `DOS-M09-005`'s `fly.toml`.
- **Decision required:** the three (or more) US geographies at which page-load and event-latency budgets are measured for the release. Recorded here with rationale (an East / Midwest / West split to bracket the coast-to-coast p95 the single-region ADR-0004 choice makes worst-case).
- **Decision path:** any change to a ratified §9 row goes through a constitution revision under CHANGE_CONTROL Rule 2a; any accepted per-release budget exception goes through an ADR under FR-9.
- **Open question:** whether the CI comparison job should hard-block on a *provisional* row miss or warn until the row is ratified. Default: fail-warn (a first miss warns; a repeat miss on the same row across N candidates blocks pending re-ratification). Revisit on measurement evidence.

### Outcome (pre-pivot)
