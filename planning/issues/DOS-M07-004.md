> **RESCOPED FOR BROWSER MVP — 2026-08-01.** [ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md) established the browser-first MVP. This card is retained with the same identity; its Outcome and FRs below are the rescoped spec. The pre-pivot spec is preserved at the bottom under "Superseded pre-pivot spec (historical record)". Disposition per [PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md](../../docs/governance/PIVOT-2026-08-01-ROADMAP-RECLASSIFICATION.md#issue-by-issue-classification): _The matrix becomes browser/engine/OS instead of iOS/Android, notification rows are removed, and storage-eviction, quota, private-browsing, multi-tab, and reconnect rows are added._

## Outcome

A risk-based conformance matrix proves the critical journeys of the hosted browser MVP across the declared browser × engine × OS floors, across the storage regimes IndexedDB actually presents in the field (persistent-granted, best-effort, evicted, quota-exhausted, private-browsing, session-only), across multi-tab writes and reconnect events, and across catalog-query degradation modes. Every executed cell yields signed evidence that ships with the release candidate; the matrix is the release evidence gate for `digitaloilsticker.com`.

## Why this matters and what it unblocks

The pivot to a hosted Phoenix LiveView application on Fly.io with IndexedDB-only personal storage ([ADR-0004](../../docs/architecture/ADR-0004-browser-first-client-and-hosting.md)) replaces every previous "prove it on a device" gate with "prove it in a browser matrix that reflects how real browsers behave." Host ExUnit and one Chrome tab cannot reveal Safari ITP eviction, Firefox private-window IndexedDB refusal, quota-exhaustion behaviour under real page weight, multi-tab last-write-wins conflicts, LiveView reconnect hydration under a real network blip, or CSP/HSTS/WSS misconfigurations at the edge. INV-5 (no implied backup) binds harder in a browser than it did on a device because clearing site data — and the browser vendors' own eviction policies — become the realistic loss scenario, and only a matrix run against real engines can distinguish "the UI honestly told the user the data is gone" from "the UI showed a fresh empty garage to a returning user." This issue produces the signed release-candidate evidence that `DOS-M07-006` needs to exit closed beta on the unlisted staging hostname and that `DOS-M07-007` needs to cut over the apex to Fly.

## Included

- Published browser support matrix — declared floors by browser × engine × OS × form-factor, versioned with the release.
- Clean-boot and hydration coverage: first mount, reconnect, deploy-restart, tab-restore.
- Connectivity states: online, degraded (packet loss / high latency), offline transitions (WSS drop), no-DNS.
- IndexedDB storage regimes: fresh open, `persist()` granted, `persist()` denied, quota under load, `QuotaExceededError`, ITP-style eviction after inactivity window, session cleared, `indexedDB.open` refused (private-browsing), `BroadcastChannel` unavailable.
- Multi-tab consistency: two tabs writing concurrently, stale-`seq` compare-and-set aborts, cross-tab re-hydration under `BroadcastChannel`, and the fallback when the channel is absent.
- Schema-version migration: forward-only migration through every prior client-payload version fixture; newer-than-server payload read-only banner.
- Locale/timezone axes retained: EN plus long-text pseudo-locale, one non-US date/unit locale, UTC / DST-observing / half-hour-offset / date-line timezones (as the browser can be driven to them via DevTools protocol or OS settings on the host under test).
- Import/export round trips including hash mismatch, oversized payload, and quarantine-list rendering.
- Accessibility axes (WCAG 2.2 AA per `DOS-M07-002`) integrated as matrix dimensions: keyboard-only desktop, screen-reader (VoiceOver on iOS/macOS, TalkBack on Android, NVDA and JAWS on Windows), large text / browser zoom, forced-colors, reduced-motion, light and dark.
- Hosted-transport verification: HTTPS-only, HSTS observed after cert verification, WSS `check_origin` rejection of a spoofed origin, CSP violation reports for a probe of each directive, session cookie flags (`Secure`, `HttpOnly`, `SameSite=Lax`) and absence of any personal value.
- Provable no-server-personal-record evidence: repo-list assertion (exactly `[CatalogRepo]`, read-only) and scripted-session log capture asserting no VIN / odometer / date / note / custom vehicle name reached logs.
- Exploratory sessions, including a final cross-functional session with a user unfamiliar with the implementation.
- Severity taxonomy, defect/waiver register, and RC gating rules.

## Functional requirements

- **FR-1 — Browser × engine × OS floors (replaces the old FR-1 iOS/Android platform floors).** Declare the minimum and current supported combinations, versioned with the release and re-checked immediately before it. The floor is a decision to be recorded with rationale in the published support policy, not frozen in this card, but the matrix MUST cover, at minimum: Safari on iOS (current and one-back), Chrome on Android (current and one-back), Chrome on Windows (current), Firefox on Windows (current ESR and current stable), Safari on macOS (current), Chrome on macOS (current), Edge on Windows (current). The engine axis (WebKit / Blink / Gecko) is recorded per cell because engine, not vendor skin, is the risk-carrying variable for IndexedDB, WSS proxying, CSP behaviour, and storage eviction. INV-1 (as amended in CONSTITUTION 2.0.0) is the source of truth for the "browser-first is the production promise" framing; do not cite the pre-amendment INV-1 in the support policy.
- **FR-2 — Matrix axes.** Define matrix axes to include: first-mount vs. reconnect vs. deploy-restart vs. tab-restore; online / high-latency / packet-loss / WSS-dropped / no-DNS; IndexedDB regime (fresh, `persist()` granted, `persist()` denied, quota under load, `QuotaExceededError`, evicted after inactivity, session cleared, private-browsing refusal, `BroadcastChannel` absent); permission surfaces used by the app (none required at MVP — clipboard for copy-share only, camera and geolocation prohibited by `Permissions-Policy`); light/dark; large text and browser zoom; forced-colors; reduced-motion; screen-reader on/off with the matching AT for the OS; EN plus long-text pseudo-locale and one non-US date/unit locale; UTC / DST-observing / half-hour-offset / date-line timezones as the browser exposes them; portrait/landscape and compact/large viewport; multi-tab (one, two same-origin, two same-origin with `BroadcastChannel` disabled). Every cell records which axis values it exercised.
- **FR-3 — Browser × OS × assistive-technology device tiers (replaces the old FR-3 physical-iPhone/Android tier).** Tier 1 (runs on every RC, must pass in full): Safari/iOS on a current iPhone (VoiceOver on/off), Chrome/Android on a current Google-reference device (TalkBack on/off), Chrome/Windows (NVDA on/off), Firefox/Windows (NVDA on/off), Safari/macOS (VoiceOver on/off). Tier 2 (per PR/nightly in CI, headless where faithful, virtual otherwise): Chromium/Blink and Firefox/Gecko headless on Linux across the automatable axes; WebKit through Playwright's WebKit build for engine parity on non-macOS hosts, with a documented note that this is not Safari. Tier 3 (per RC, exploratory): Edge/Windows (Narrator on/off), JAWS on Windows (one journey minimum, since JAWS licensing constrains breadth), one supported low-mid-tier Android/OEM Chrome build for storage-eviction and quota behaviour on lower-memory devices. XCUITest, Espresso, Appium, `mob_*` bindings, and physical-iOS clock manipulation are explicitly out of scope for this matrix — the previous FR-3's device tiers are retired here.
- **FR-4 — Scripted critical journeys.** Script every browser-MVP critical journey: cold URL entry → skeleton → hydration to `:loaded` or `:empty` or `:storage_unavailable` (per ADR-0004 first-paint rules); vehicle search and select against `CatalogRepo`; interval provenance and confidence rendering; service and reading capture with the round-trip acknowledgement contract (INV-24); forecast evolution; in-app due/overdue rendering (INV-17 as amended — no OS notifications are asserted or scheduled); reminder-preference edit; export as file download and import as file upload (INV-5, INV-25); replace-vs-merge preview; forward migration from every prior stored `schema_version` fixture; newer-than-server payload read-only banner; storage-denied session-only mode; `QuotaExceededError` failed-ack path; evicted-storage `:data_missing` warning; two-tab last-write-wins with visible loss.
- **FR-5 — Per-run evidence record.** For every executed cell record: release identifier (immutable, from `DOS-M09-006`), catalog `data_version`, storage `schema_version`, browser + engine + OS + AT versions, viewport, network profile applied, preconditions (IndexedDB seed fixture used), timestamps, actual result, server logs from the matching request window (filtered per `DOS-M09-008` redaction), Phoenix `handle_event` name log (no params), browser console log, HAR of network activity, screenshots, video for manual runs, and defect link. Seed fixtures through the same import path a user would use (`local_store:hydrate` with a prepared envelope); user-facing tests never mutate the database file or the IndexedDB store outside the app's own hooks.
- **FR-6 — Severity taxonomy and RC gating (retained, restated for the hosted product).** S1: data loss (browser-storage record silently discarded), transport-security regression (mixed content, missing HSTS after verification, `check_origin` accepts a foreign origin), or a server-side personal record leak (any assertion in FR-8 fails). S2: incorrect due/overdue state, false empty-garage flash on reconnect, hydration timeout with silent skeleton, blocked core or accessibility journey (WCAG 2.2 AA regression), CSP violation caused by app code. S3: degraded/noncritical. S4: cosmetic. S1/S2 block the RC; only product + engineering + QA together may time-box a documented S3 waiver.
- **FR-7 — Hydration, reconnect, and multi-tab conformance (new; replaces the retired native FR-7 killed-app/reboot/timezone notification requirement).** Prove per ADR-0004: hydration is idempotent (same envelope twice → identical assigns, no write-back); the pre-hydration skeleton is visually distinct from `:empty`; a reconnect after a deploy restores the same view (client DOM retained under `phx-disconnected`, assigns replaced underneath); pending optimistic mutations survive a reconnect and are re-driven from client storage; a stale-`seq` write aborts inside the same IDB transaction and surfaces `local_store:conflict`; the losing tab re-hydrates; when `BroadcastChannel` is unavailable the compare-and-set still prevents lost-update corruption. Explicitly recorded: the retired FR-7 was "actual notification behavior for killed app, reboot, timezone travel, and permission revocation on both OSes"; the browser MVP has no scheduled OS notifications (INV-17 as amended, ADR-0004 §"Consequences"), so no cell of this matrix asserts a delivery.
- **FR-8 — Storage-eviction, quota, private-browsing conformance (new).** Prove: `navigator.storage.persist()` is called once after the first meaningful write, its result recorded honestly in the storage-status UI (granted / denied / unavailable), and never described as "backup"; `navigator.storage.estimate()` at hydration and the 80%-of-quota surface; a `QuotaExceededError` triggers the failed-ack persistent "Not saved to this browser" affordance with export offered — data is never silently dropped; the fallback ladder to session-only mode (with permanent banner) executes when `indexedDB.open` throws; the `:data_missing` warning appears when `dos_boot_state == "has_data"` but hydration returns zero records; ITP-style eviction on WebKit after an inactivity window is exercised via time-warping the browser profile and the loss is rendered as `:data_missing`, not as a fresh empty garage.
- **FR-9 — Catalog-query degradation conformance (new).** With `DOS-M09-005` in place, prove: p95 query latency within `DOS-M07-003`'s rescoped budget on a US-median connection profile; per-socket rate limits reject a probe burst with a rendered, non-fatal state (not a crash); WSS drop mid-search returns to a rendered, retryable state; a `SIGTERM` (deploy) mid-query reconnects and re-hydrates without losing local records; queries carry no personal parameter (INV-26) — a diff of outbound socket messages against a personal-token allowlist is part of the evidence bundle.
- **FR-10 — Internet-facing transport, CSP, and no-server-personal-record verification (new; ties the matrix to `DOS-M09-008`/`DOS-M07-001`).** Every RC run includes: HTTP → HTTPS redirect; HSTS header present (only after cert verification per ADR-0004); WSS `check_origin` rejects a foreign origin under an explicit probe; CSP directives produce report-only violations for scripted probes; the deployed Ecto repo list is exactly `[CatalogRepo]` and its connection is read-only (asserted at boot); the scripted-session log capture from ADR-0004 §"Enforcement" runs and asserts no VIN / odometer / date / note / custom vehicle name / `tab_id` appears in any log line; `debug_errors: false` verified in production configuration.
- **FR-11 — Final exploratory session.** Include design, engineering, QA, and a user unfamiliar with the implementation, with browser DevTools, network throttling, storage panels, and AT open. Their charter is to break INV-5 and INV-25 (make the UI imply backup) and INV-24 (find a state combination that flashes an empty garage on a returning user).

## Technical implementation contract

### Components and ownership boundaries

- Matrix definition, scripts, dashboard, and defect/waiver register: owned by the QA workstream (this card).
- Automated Tier-2 conformance suite: defined by `DOS-M09-009`, wired into `DOS-M07-005`'s CI (per PR / nightly). This card consumes it and adds the RC-gated Tier-1 and Tier-3 runs that require real browsers, real AT, and human-observed exploratory sessions.
- Support-policy document: co-owned with release management; declares the FR-1 floors; consumed by `DOS-M07-007` and the public support page on the Netlify static side.
- Storage-behaviour test hooks (a small module the LiveView exposes only when a build-time flag is set) are implemented by the owning workstreams to QA's specification and drive the app the same way a user's hook would (via `local_store:hydrate` envelopes) — user-facing tests never poke the browser storage layer directly.

### Data and persistence

- Storage fixtures: an immutable set of IndexedDB payload envelopes for every prior `schema_version`, covering healthy garages, oversized garages (cap edges), quarantine-triggering invalid records, and pre-migration shapes. Kept under version control alongside the migration functions from `DOS-M09-001`.
- Catalog fixtures: pinned to specific `data_version`s so a matrix run is reproducible; the Fly release identifier plus catalog `data_version` pin every cell.
- Test-run records, evidence files (screenshots, HAR, video, log captures), and the defect/waiver register live with the release candidate and contain fixture data only (no real personal data, per INV-4/INV-23).

### Interfaces and events

- Matrix scripts drive the app through browser automation (Playwright as the primary tool: it drives WebKit, Chromium, and Firefox from one script surface; supports CDP-based time and clock control on Chromium; supports realistic network profiles; and can run headed on macOS/Windows for engine-faithful cells). Selectors are the stable `data-testid`s from `DOS-M07-002`. XCUITest, Espresso, Appium, and `mob_*` bindings are explicitly not part of this matrix.
- AT verification uses the real assistive technologies on real hosts (VoiceOver/macOS, VoiceOver/iOS, TalkBack, NVDA, JAWS) — automation harnesses are used to reach the state under test; the AT observation itself is human, recorded, and attached.
- Storage-state verification observes both `socket.assigns` (via the test hook) and the raw IndexedDB state (via the browser's storage inspector, captured to the evidence bundle) — both must agree.
- Results feed the dashboard as structured records (FR-5 fields), traceable from matrix cell to evidence.

### Failure and recovery behavior

- The matrix itself tests failure/recovery: quota exhaustion, storage-denied fallback, evicted-storage recovery via import, multi-tab conflict with visible loss, hydration timeout, WSS drop, deploy mid-session, migration of every prior stored version, newer-than-server read-only mode.
- A failed cell produces a defect with severity per FR-6; flaky/unreproducible results are recorded and investigated, never re-run to green silently.
- If a Tier-1 browser × OS × AT surface cannot be exercised (vendor outage, device unavailability), the gap is documented and the RC does not pass until the cell is executed or explicitly waived per the S3-only waiver rule (S1/S2 scope may never be waived).

### Security and privacy

- Every FR-10 assertion doubles as internet-facing privacy-boundary verification, consistent with `DOS-M07-001` (rescoped) and `DOS-M09-008`.
- The scripted-session log capture from ADR-0004 §"Enforcement" runs as a release gate here, not only in unit CI, and its output is attached as evidence.
- Any hosting-vendor artifact (Fly log tail, machine metrics) attached to a defect must first pass the FR-10 redaction check; no raw tail from a live socket is ever attached to a defect ticket.
- LiveDashboard is verified disabled in production during the run (ADR-0004 §"LiveDashboard and operator access").
- Device-cloud vendor use for Tier-1 and Tier-3 cells must not upload personal data (fixtures only) and complies with the no-third-party rule (INV-4). The vendor is documented per RC.

### Accessibility and performance

- Accessibility axes are integrated matrix dimensions per `DOS-M07-002`; a blocked accessibility journey is S2. Keyboard-only desktop use is a first-class Tier-1 cell that the pre-pivot device matrix did not cover.
- Matrix runs occur on budget-verified builds per `DOS-M07-003` (rescoped); observed page-load, time-to-hydrated, LiveView round-trip, server-memory-per-socket, or IndexedDB-footprint regressions are logged as defects against those budgets.

## UX and content states

- The matrix exercises every shipped UX state: pre-hydration skeleton (distinct from `:empty` and `:storage_unavailable`), `:loaded`, `:empty`, `:storage_unavailable`, `:data_missing`, newer-than-server read-only banner, quarantine-list rendering after partial-valid hydration, session-only banner, storage-status surface with honest `persist()` result and quota estimate, catalog-query failure and retry, WSS-dropped reconnect, deep-link entry (search/select URL) with correct pre-hydration, in-app due/overdue and reminder-preference states, export-download preview, import file-picker with replace-vs-merge preview, localization expansion (long-text pseudo-locale, non-US date/unit locale).
- Prohibited words in this UI (per ADR-0004 §"Export and import" and INV-25) are asserted absent in every screenshot pass: "backup", "synced", "safe", "we'll remember", "your account".
- No new UX is created; gaps found in states are defects, not scope to patch ad hoc.

## Rollout and rollback

The matrix is a release gate, not a rollout: it runs against each release candidate pinned to an immutable Fly release identifier and a catalog `data_version`. If the RC fails the gate, the candidate is rejected and a new build enters the same matrix; there is no partial pass. The published browser-support policy is versioned; narrowing it (dropping a browser floor) after publication is a release-note-visible decision, not a silent edit. Matrix definitions and scripts are version-controlled with the release they validated. Rollback of a shipped release is a Fly image redeploy per `DOS-M09-006`; the matrix does not need to re-run for a rollback to a previously-signed release identifier, but must re-run for any hotfix RC.

## Risks, decisions, and open questions

- Risk: **browser-vendor drift between matrix definition and release** (a Safari point release changes ITP timing, a Chrome release tightens `SameSite`, a Firefox update changes IndexedDB error semantics). FR-1 mandates a re-check immediately before release; the support-policy document records the exact browser versions the RC was validated against.
- Risk: **ITP-style eviction cannot be faithfully reproduced by any automation available today** (WebKit-through-Playwright is not Safari; time-warping a real device profile is disruptive). Mitigation: at least one real Safari/iOS cell per RC exercises the eviction path via a controlled profile time-shift and human observation, and the resulting behaviour is recorded verbatim.
- Risk: **assistive-technology licensing and access** (JAWS licences are commercial; VoiceOver/iOS requires an iPhone in the QA pool). Mitigation: Tier-3 records "one journey minimum" on JAWS with the constraint documented; a shared iPhone in the QA pool is a hard prerequisite for RC pass.
- Risk: **device-cloud vendors may retain artifacts.** Mitigation: fixtures-only rule (INV-4/INV-23), post-run cleanup asserted, vendor documented per RC; a change of vendor is a support-policy change, not a silent switch.
- Risk: **the browser is an adversary of the user's storage** — R1 in ADR-0004. The matrix is the primary place this risk gets measured; a discovered eviction anomaly may reopen the PWA-install decision (`DOS-M09-010` spike).
- Decision required: the concrete FR-1 browser × engine × OS floors and the Tier-1 device models — recorded in the published support policy with rationale and evidence.
- Decision recorded: severity taxonomy and waiver rule (FR-6) govern RC gating; only product + engineering + QA jointly may time-box an S3 waiver.
- Decision recorded: the pre-pivot native FR-7 (killed-app/reboot/timezone notification behaviour on iOS and Android) is retired because the browser MVP has no OS-scheduled notifications (INV-17 as amended, ADR-0004 §"Consequences"); the historical wording is preserved in the "Superseded pre-pivot spec" section for the eventual native re-entry.
- Open question: **whether Playwright's Firefox and WebKit builds are engine-faithful enough for Tier-2** to substitute for real Firefox and real Safari on the automatable axes. The RC-gating cells always use real browsers on real OSes; the open question is only how much CI-time signal the Playwright builds provide.
- Open question: **how to reach a genuine ITP-eviction state in CI at all.** Currently only a real Safari/iOS Tier-1 cell reaches it; if a reliable simulation appears it may promote to Tier-2, otherwise it stays a manual RC step.

## Definition of done

- All FRs implemented; all ACs checked with linked evidence.
- Matrix dashboard complete for the release candidate; QA-signed summary attached.
- Zero open S1/S2; all waivers S3-only, documented, time-boxed, and jointly approved.
- Browser-support policy (FR-1 floors) published and consumed by `DOS-M07-007` and the Netlify static support page.
- `DOS-M07-006` exit and `DOS-M07-007` are unblocked with the signed evidence they require.

### Technical implementation contract (pre-pivot)

#### Components and ownership boundaries

- Matrix definition, scripts, dashboard, and defect/waiver register: owned by the QA workstream (this issue).
- Supported test hooks for fixture seeding: implemented in the app codebase by the owning workstreams to QA's specification; user-facing tests never use manual database surgery.
- Support-policy document: co-owned with release management; consumed by DOS-M07-007 and store metadata.
- Automated Tier-2 runs: wired into the DOS-M07-005 CI (per PR/nightly); Tier-1 physical runs are release-gated manual/assisted procedures.

#### Data and persistence

- Upgrade fixtures: an installable artifact/data image for every supported schema/catalog baseline, maintained as immutable fixtures (aligned with DOS-M07-005 migration CI).
- Corrupt-database and disk-full fixtures for storage/migration recovery scripts.
- Test-run records, evidence files, and the defect/waiver register are stored with the release candidate, containing fixture data only (no real personal/vehicle data).

#### Interfaces and events

- Matrix scripts drive the app through UI automation (XCUITest/Espresso/Appium) using the stable IDs from DOS-M07-002, plus documented supported test hooks for state seeding and clock/timezone control where the platform permits.
- Notification verification observes the OS-level scheduled/delivered state, not just app-internal `scheduled_notifications` rows — both must agree.
- Results feed the dashboard as structured records (FR-5 fields), traceable from matrix cell to evidence.

#### Failure and recovery behavior

- The matrix itself tests failure/recovery: storage pressure, corrupt fixture, interrupted migration recovery, killed-app and reboot delivery, permission revocation.
- A failed cell produces a defect with severity per FR-6; flaky/unreproducible results are recorded and investigated, never re-run to green silently.
- If a Tier-1 device cannot complete the run (hardware/OS issue), the gap is documented and the RC does not pass until the cell is executed or explicitly waived per the S3-only waiver rule (S1/S2 scope may never be waived).

#### Security and privacy

- Privacy reset, export-reset-import, and permission-revocation scripts double as privacy-boundary verification, consistent with DOS-M07-001.
- Evidence (screenshots/video/logs) uses fixtures; native/BEAM logs attached to runs must already comply with the DOS-M07-001 redaction rules.
- Device-farm usage must not upload user data (fixtures only) and complies with the no-telemetry rule.

#### Accessibility and performance

- Accessibility axes (large text, screen reader, light/dark) are integrated matrix dimensions, reusing the DOS-M07-002 checklist; a blocked accessibility journey is S2.
- Matrix runs occur on budget-verified builds; observed performance anomalies during runs are logged as defects against the DOS-M07-003 budgets.

### UX and content states (pre-pivot)

- The matrix exercises every shipped UX state: first offline boot, no-result/manual fallback in vehicle selection, unknown/unsupported provenance states, permission-denied fallback, due/overdue states, notification deep link, export/import/reset confirmations, storage-pressure and corruption-recovery surfaces, and localization expansion (long-text pseudo-locale, non-US date/unit locale).
- No new UX is created; gaps found in states are defects, not scope to patch ad hoc.
