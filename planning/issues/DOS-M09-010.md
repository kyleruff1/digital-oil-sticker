## Outcome

Every data source feeding the hosted catalog carries a recorded, source-specific authorization disposition across six separate dimensions (copyright basis, acquisition basis, redistribution basis, trademark posture, claim posture, review status), the project's factual-use and referential-trademark policies are adopted and enforced by build gates, and every compatibility or interval statement the product can render is backed by field-level substantiation. This replaces the earlier single-axis "hosted-serving rights re-review": sources are approved or withheld for the *specific* thing that is unresolved, never blanket-gated because a source is private, and never per-row-reviewed when the source-level basis already covers harmless identity facts.

## Why this matters and what it unblocks

The pivot to a hosted app changed the legal surface: serving facts from a public origin, using vehicle and product names as identifiers, and rendering derived compatibility results each raise different questions (copyright, access terms/contract, trademark, FTC substantiation) that a single `rights_disposition` flag conflated. Getting this right unblocks the entire vendoring value chain — the vPIC/FEG identity catalog (DOS-M09-004 serving path), the independently authored oil brand/family list (`ProductSelect`), the M03 acquisition tickets, and the future recommendation surface — while keeping the one genuinely restricted source (API EOLCS) correctly contained. Cites INV-15 (provenance + basis for network serving), INV-16 (claims discipline), INV-20/21 (terminology), INV-26 (impersonal queries).

## Excluded

- Any bulk scraping or mirroring of the EOLCS directory; any use of API certification-mark graphics (donut/starburst/shield) or any manufacturer logo.
- Copying source prose, manual text, table layouts, photography, or label artwork into the catalog or UI.
- Declaring the catalog "fair use" as its primary legal basis; fair use remains a fallback for limited, attributed excerpts only.
- The final pre-launch legal review itself (a lawyer reviews the EOLCS acquisition method and public recommendation copy before launch — a launch gate in RELEASE_GATES.md, not closed here).
- UK/EU territory review.

## Functional requirements

- FR-1: `data_sources` carries the six disposition dimensions with the exact enums from the factual-use policy; the compiler withholds a row when its acquisition method, redistribution basis, or resulting claim posture is unresolved — and does not withhold harmless identity fields from a source-level-approved source.
- FR-2: vPIC and FuelEconomy.gov disposition rows are recorded as approved with their separate authorization evidence (vPIC: open-data FAQ citation + factual extraction; FEG: download-page + DOE policy citation, dataset URL, retrieval date, file hash, documentation version, field-notice review).
- FR-3: The EOLCS disposition row records pending/prohibited acquisition and unknown redistribution with dated snapshots (terms SHA-256, robots.txt copy) as evidence — and the build fails if any EOLCS-sourced row reaches the artifact while that stands.
- FR-4: The independent oil product list stores only factual fields (`brand_name, product_family, product_variant, viscosity_grade, service_category_claim, oem_spec_claims, product_url, data_sheet_url, source_observed_at, source_type, verification_status`) and never ingests marketing prose, photography, label artwork, logos, or certification-mark images.
- FR-5: The referential trademark policy is enforced: plain-text identifiers only, app typeface, no third-party logo assets anywhere in the repo or artifacts (build test), no manufacturer name in the product lockup, no ®/™.
- FR-6: The no-affiliation statement (verbatim from the policy) and source attribution render on a public page of the app.
- FR-7: Match results are a distinct record kind carrying `algorithm_version`, `matched_fields`, `unresolved_fields`, `conflicts`, and one of `verified_match | partial_match | insufficient_data | conflict | not_applicable`; absent requirements can never produce `verified_match` (proven by test).
- FR-8: Claim-language rules are lint-enforced: `best oil`, `guaranteed`, `warranty safe`, `manufacturer approved`, `API approved`, `recommended by`, `works with every` fail the build anywhere in UI copy; "Meets the recorded requirements" appears only on full mandatory-requirement matches.
- FR-9: Affiliate/sponsorship fields exist on recommendation-surface records and are always false in this build.
- FR-10: Field-level source locators and observation dates exist on every requirement and product-claim row.

## Technical implementation contract

### Components and ownership boundaries

Policies live in `docs/`; enforcement lives in the catalog compiler quality gates (`tools/catalog/src/checks/`), the app copy-lint test, and the asset-scan test. `Catalog.SourceGate` reads the disposition dimensions (not a single flag) plus `catalog_metadata.feature_*`. The independent oil list lives at `tools/catalog/data/curated/oil_products.yml` with a loader that hard-fails rows missing provenance.

### Data and persistence

`data_sources` DDL gains the six enum columns plus `terms_sha256`, `evidence_ref`, `reviewed_at`, `reviewer`. Oil rows carry `verification_status` and reference their source row. No user-side storage change.

### Interfaces and events

`catalog_metadata.feature_oil_products` distinguishes `enabled` (independent list serving) from `withheld`; the query layer renders the honest INV-11 state either way.

### Failure and recovery behavior

A disposition regression (a source's terms change) is a data edit + rebuild; the deploy gate re-runs disposition checks against the artifact inside the image and fails closed naming source, dimension, and predicate.

### Security and privacy

A source condition requiring per-request identifiers or usage reporting is automatically prohibited (INV-3/4/26). Evidence snapshots contain no credentials.

### Accessibility and performance

N/A — policy/gating issue; the attribution page follows the app's standing accessibility bar.

### Data change specifics

Source/version/license: each `data_sources` row records provider, dataset, canonical URL, `terms_sha256`, and the six disposition enums with `reviewed_at`/`reviewer`. Mapping/stable keys: dispositions key by stable source id; oil rows key by UUIDv5 over (brand, normalized product name). Constraints/indexes: enum CHECKs on all six dimensions; withheld-by-default on absent/malformed values. Idempotency: re-running the compiler with unchanged inputs yields byte-identical dispositions. Rejected-row policy: rows failing provenance or disposition checks are reported and excluded, never silently dropped. Checksums: evidence snapshots hashed; artifact SHA in the manifest. Coverage report: per-source disposition summary emitted each build. Fixture strategy: gate-violation fixtures (pending-EOLCS row, missing-provenance row) must fail the build. Update cadence: dispositions re-reviewed on any source-terms change and before each catalog release. Rollback/recovery: disposition edits are data changes + rebuild; prior artifacts remain in history.

## UX and content states

The attribution page lists sources with attribution text and the verbatim no-affiliation statement. Independent-list product rows render plain-text names with "As of {source_observed_at}"; user-entered products carry the "User entered" badge. No state may imply sponsorship, approval, or endorsement.

## Test plan

### Automated

- Compiler gate fixtures: an EOLCS-sourced row with pending review fails the build; an independent-list row missing `source_observed_at`/`product_url` fails; a source with `redistribution_basis: unknown` withholds its non-identity rows.
- Copy-lint: the FR-8 avoid-list fails anywhere in `copy.ex`/HEEx; mandated replacements render.
- Asset scan: no third-party logo/certification-mark asset in the repo or artifacts; no `<img>` src referencing one.
- Match-result tests: absent requirement → never `verified_match`; every derived result carries `algorithm_version`.

### Manual/browser matrix

- Attribution page renders the verbatim no-affiliation statement and per-source attribution at 100%/200% zoom.
- Spot-check product rows render plain text in app typeface (no logos) across the browser matrix.

## Rollout and rollback

Policies take effect at merge; gates ship with the compiler and app test suite. A later EOLCS approval is a data change to `data_sources` plus rebuild — no code change. No migration is needed from the old single-gate scheme because no production rows were ever emitted under it.
